# Pulse Clusters 0.14.7 — запуск на сервере 10.129.160.10

**Ошибка Astra AI HTTP 401 в Анализе проблемы:** [адресное исправление 0.14.1 без перенастройки остальных разделов](docs/UPDATE-0.14.1-RU.md).

**У вас уже работает Pulse:** начните с [обновления до 0.14.7 с сохранением PeopleHub, qwen и истории](docs/UPDATE-0.14.7-RU.md). Новая установка ниже нужна только для пустого сервера.

Выполняйте команды последовательно. Если команда вернула ошибку, сначала устраните её; не переходите к следующему этапу. На сервере запускается приложение, на вашем компьютере — SSH-туннель и браузер.

## 1. Проверить сервер

В SSH-сессии сервера:

```bash
cat /etc/os-release
uname -m
python3 --version
docker version
docker compose version
git --version
```

Нужны Linux, Python 3.12+, Docker Engine (в выводе должны быть Client и Server), Compose plugin с поддержкой `up --wait` (v2 и новее). Архив с wheelhouse проверен на x86_64/amd64. Для Ubuntu 24.04 Python 3.12 доступен в штатных пакетах. Установка Docker зависит от ОС: https://docs.docker.com/engine/install/. Команды Ubuntu нельзя применять к RED OS. Для установки системных пакетов нужны административные права.

Если `docker version` сообщает permission denied, используйте учётную запись с разрешённым доступом к Docker или согласованный sudo. Не меняйте socket на режим 777.

## 2. Получить приложение из приватного GitHub

Если каталога ещё нет:

```bash
cd ~
git clone https://github.com/Ivan-Shkutov/new.git pulse-clusters
cd ~/pulse-clusters
```

Git должен иметь доступ к вашему приватному репозиторию. GitHub не принимает обычный пароль аккаунта для Git HTTPS: используйте свой настроенный credential manager/GitHub CLI/SSH-доступ. Не вставляйте токен в URL, команды или переписку. Если на сервере нет GitHub-аутентификации, скачайте архив и SHA256 из раздела `releases` через авторизованный браузер на своём компьютере, передайте по SCP и следуйте разделу 9 [INSTALL-RU](docs/INSTALL-RU.md).

Если проект уже установлен, используйте раздел обновления ниже. Не удаляйте существующий каталог.

## 3. Создать настройки и запустить

```bash
./pulse init --port 8090
./pulse start
./pulse status
./pulse check
cat runtime/secrets/portal-password
```

Первая сборка загружает закреплённый базовый образ. Git-установка также загружает Python-пакеты; complete-архив содержит проверяемый wheelhouse. Команда check должна показать `status: ok`, версию 0.14.0 и ответ `/api/overview`. Пустой список кластеров при новой установке нормален.

Логин: `pulse`. Пароль создаётся случайно и хранится в указанном файле. Не присылайте пароль в чат. Не удаляйте runtime/registry.key: он нужен для расшифрования подключений.

## 4. Открыть панель с Windows

На своём компьютере, в новом PowerShell:

```powershell
ssh -N -L 8090:127.0.0.1:8090 dito@10.129.160.10
```

Используйте своё SSH-имя вместо `dito`, если оно другое. Отсутствие вывода при работающем туннеле нормально. Оставьте окно открытым. В браузере откройте http://127.0.0.1:8090 и войдите.

Если локальный порт занят:

```powershell
ssh -N -L 18090:127.0.0.1:8090 dito@10.129.160.10
```

Тогда адрес браузера: http://127.0.0.1:18090. Не открывайте наружу HTTP-порт панели; для постоянного общего доступа нужен HTTPS reverse proxy.

Подробная последовательность подключения и приёмки: [CONNECT-CLUSTER-RU](docs/CONNECT-CLUSTER-RU.md).

## 5. Добавить Kubernetes

На машине с административным kubectl выполните команды из [раздела 3 INSTALL-RU](docs/INSTALL-RU.md#3-kubernetes): примените `deploy/rbac-readonly.yaml`, проверьте права и создайте kubeconfig скриптом `scripts/export-kubeconfig.py`.

В панели: «Настройки» → «Добавить» → ID (например, peoplehub), название, reader kubeconfig → сохранить. Не загружайте административный kubeconfig. Указанный API endpoint должен быть доступен с 10.129.160.10; отключать TLS-проверку нельзя. Полученный краткосрочный токен нужно обновлять до истечения срока.

Откройте «Ресурсы» и нажмите «Собрать сейчас». Сравните Nodes/Pods/Namespaces с kubectl. Неполные права и недоступные ресурсы должны отображаться ошибкой/неполнотой, а не исправным пустым кластером.

## 6. Метрики, Astra и модель

- **Метрики:** в настройках кластера введите URL Prometheus/VictoriaMetrics до `/api/v1/query`. Для общего источника задайте реальные labels, например `{"cluster":"peoplehub"}` только если такая метка действительно есть. Для отдельного источника выберите dedicated. Отсутствие метрики не равно нулю.
- **Astra logs:** URL, сервисный bearer token, точные поля cluster/namespace/pod. Схема API зависит от установленной Astra и требует проверки. Astra incidents в этой версии не реализованы.
- **LLM:** в «Настройках» укажите работающий OpenAI-compatible endpoint, например `http://127.0.0.1:8002/v1`, точный model ID и при необходимости API key. Сохраните и нажмите «Проверить ответ». vLLM, GPU-драйверы и веса модели устанавливаются отдельно; их конфигурацию нельзя выбрать достоверно без данных о GPU и модели.
- **HolmesGPT:** необязательный режим с ограниченными инструментами чтения. [Генерация конфигурации, запуск и проверка фактического tool call](docs/HOLMES-RU.md).

Изменение URL интеграции удаляет старые credentials из сохраняемой конфигурации: для нового адреса задайте их заново. Без модели инвентарь работает, но анализ LLM недоступен.

## 7. Проверить полезный сценарий

Загрузите в «Базу знаний» небольшой MD/TXT с описанием приложения без секретов. Найдите его по уникальному слову. Выберите Pod, прочитайте логи и запустите расследование. Проверьте, что ответ использует реальные факты; текст модели остаётся гипотезой. После реального устранения проблемы сохраните проверенное решение. Повторное открытие страницы должно сохранить историю.

## 8. Резервное копирование и обновление

В каталоге установленного проекта:

```bash
./pulse backup --output-dir "$HOME/pulse-backups"
./pulse stop
git status --short
git pull --ff-only origin main
./pulse start
./pulse check
```

Backup содержит credentials: храните его защищённо и отдельно от сервера. Если у вас есть локальные изменения, разберите их до pull. Не удаляйте runtime и не выполняйте `git reset --hard`. Повторный init для обновления не нужен. Полный порядок restore описан в [INSTALL-RU](docs/INSTALL-RU.md#6-остановка-и-резервные-копии).

## 9. Что прислать при ошибке

Нужны название неудавшейся команды, сообщение об ошибке, версия ОС, Python и Docker. Для сбоя запуска: `./pulse status` и относящийся к ошибке фрагмент `./pulse logs`. Перед отправкой удалите пароли, токены, kubeconfig и внутренние данные. Не присылайте runtime/.env, registry.key или backup целиком.

**Статус:** проверки приложения перечислены в [QA-RU](docs/QA-RU.md). Ваш сервер, маршруты, Kubernetes, Astra и модель удалённо ещё не проверялись. Один административный аккаунт; нет HA, AURA, PostgreSQL/Qdrant и автоматического исполнения исправлений. Живая связка Holmes с вашей моделью требует отдельной приёмки.
