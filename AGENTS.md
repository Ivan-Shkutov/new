# Pulse: правила работы для Codex

- Работайте только с Pulse Clusters в этом репозитории. Проект частного облака Cloud ведётся отдельно.
- Начинайте с симптома и связанных файлов; не перечитывайте весь репозиторий и не запускайте полный набор проверок без причины.
- Карта кода: `app.py` — API и настройки; `connectors.py` — Kubernetes/метрики/внешние источники; `health.py` и `dashboard.py` — состояние Обзора; `diagnostics.py` и `cluster_chat.py` — расследование и ИИ; `knowledge.py` — знания; `static/` — интерфейс. Сначала открывайте соответствующий `tests/test_*.py`.
- Считайте `docs/CODEX-STATE-RU.md` кратким рабочим контекстом, но сверяйте его с кодом и `git status`: файл может устареть.
- Сбор Kubernetes и расследования должны оставаться read-only. Не выполнять исправляющие команды в кластере автоматически.
- В Обзоре и ответах ИИ различайте факт, гипотезу, отсутствие данных и ошибку источника. Указывайте время, полноту и источник данных.
- Расследование связывайте с выбранным cluster/namespace/name/UID; новый Pod не выдавайте за старый. Не утверждайте причину без подтверждающего события, статуса, лога или метрики.
- Не печатайте и не коммитьте токены, kubeconfig, пароли, модельные ключи и runtime. Для внешних интеграций mocks не доказывают работу с живым кластером/Astra/LLM.
- Проверяйте сначала конкретный изменённый сценарий; полный `pytest` запускайте для сквозных изменений или перед выпуском. Сообщайте, что проверено вживую, а что только локально.
- Перед завершением обновляйте краткое состояние в `docs/CODEX-STATE-RU.md`, если поменялись версия, подтверждённые проблемы или результат проверки.
- После каждого исправления в итоговом ответе указывайте точную версию/build ID, давайте команды обновления с backup и сохранением действующего runtime, проверку результата и способ отката. Пользователь просит присылать порядок обновления каждый раз, а не только ссылку на инструкцию. Если выпуск ещё не собран, прямо сообщайте об этом.
- Для локальной задачи достаточно одного исполнителя. Подагентов используйте только для действительно независимых частей: общий лимит использования расходуется быстрее.
