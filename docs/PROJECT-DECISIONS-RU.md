# Принятые решения по десяти вопросам

Пользователь поручил выбрать параметры самостоятельно. Это целевая конфигурация и критерии приёмки, а не выдуманный отчёт об установленном сервере. Две A30 по 24 GiB остаются у существующего vLLM/Qwen; повторное скачивание весов не требуется.

1. **Версия.** Повторный аудит выполнен от опубликованного 0.16.0. Новый комплект — 0.16.1; обновление обнаруживает фактическую текущую версию, контейнер и runtime. Последняя предоставленная серверная версия была 0.15.1; применение 0.16.0 пользователем не подтверждено.
2. **Приоритет.** Сначала законченный ответ по настоящему инциденту, правильные UID/время и честная диагностика отказа. Затем качество гипотез/проверок и документации. Краткость важнее длинного перечисления возможных причин.
3. **Кластеры и продукты.** Несколько изолированных подключений Kubernetes, VK Teams on-prem, VK Почта и Astra. Peoplehub — известное имя кластера, не доказательство его доступности из этой среды. Версию Kubernetes читать из API; версии приложений и происхождение документации задавать по фактической установке. Не выбирать фиктивную версию для поиска.
4. **Данные.** Только разрешённое чтение статусов, событий, владельцев, реплик, Service/EndpointSlice, current/previous логов и доступных метрик/Astra. Логи Pod: до 500 строк/256 KiB на запрос, с проверкой UID до/после чтения. История: finishedAt ±30 минут, если это время доступно; иначе последние шесть часов с явным указанием, что время сбоя неизвестно. Это окно запроса, не гарантия хранения данных. Нужные проверки определяет профиль симптома; недоступные источники видны как пробелы.
5. **Основной движок.** Целевой режим — Holmes с инструментами Pulse только для чтения. Включать после проверки защищённого API, ответа и инструментального nonce. Прямой vLLM — явный самостоятельный режим. Рабочее подключение не заменять непроверенным; скрытого переключения провайдера нет. n8n в критическом пути расследования не требуется.
6. **Нагрузка.** Один активный разбор Pulse и один ожидающий. Через 60 секунд ожидающий запрос завершается понятной ошибкой; закрытый ожидающий запрос удаляется вместе с данными. Настройки Compose: `PULSE_AI_WORKERS=1`, `PULSE_AI_QUEUE=1`, `PULSE_AI_QUEUE_WAIT=60`. Это не ограничитель запросов от самой Astra/VK-ботов к vLLM. Повышать параллельность после измерений задержки при совместной нагрузке.
7. **Время и объём.** Цель приёмки: краткий ответ примерно за минуту, полный обычно за 3–5 минут; измерить на реальной Qwen, не считать гарантией. Технические бюджеты: native 8192 токена/300 секунд; Holmes 8 итераций, 4096 токенов/180 секунд на model call, Pulse ждёт до 600 секунд. Генерация до лимита не обязательна. Первый полный ответ — шесть разделов до 450 слов, уточнения обычно до 150 слов. Контекст приложения — 240 000 символов суммарно, не токенов; превышение отклоняется явно, доказательства не обрезаются скрыто. Ограничение модели по токенам проверяет vLLM.
8. **Библиотека.** Контролируемые MD/ZIP/TAR из папок продуктов с manifest product/version/source. Watcher, чанки и повторная публикация автоматические; скачивание произвольных сайтов не включается. CPU embeddings и Qdrant сохраняют GPU для Qwen. Начать с небольшого корпуса и проверить нужную версию/цитаты. Отсутствие документа не заполняется выдуманной ссылкой.
9. **Доступ.** Текущая модель Pulse — один администратор, внутренняя сеть и HTTPS с настоящей аутентификацией. Существующий пароль и ключ сохраняются при обновлении. SSO, роли и разграничение пользователей не заявлены реализованными. Для внешнего доступа применить существующий HTTPS deployment; прокси, автоматически подставляющий admin Authorization, сам по себе не защищает вход.
10. **Приёмка.** Три случая из чата: EmptyDir выше 1Gi; `infowatch SendText`; `cox filter create error: sn is empty`. Правильные ограничения выводов и проверки описаны в [ACCEPTANCE-CASES-RU.md](ACCEPTANCE-CASES-RU.md). Дополнительно проверить неправильный UID, отсутствие документации, timeout и заполненную очередь. Результат тестового HTTP-макета не выдавать за качество реальной Qwen/Holmes.

Активная генерация на удалённом сервере может продолжаться после закрытия окна или клиентского timeout. Отмена ожидающей задачи не означает отмену активного запроса к vLLM/Holmes. Для жёсткой общей квоты нескольких приложений нужен отдельный механизм на входе vLLM, проверенный со всеми его клиентами.
