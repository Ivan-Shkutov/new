# Pulse 0.14.1 — адресное исправление «Анализа проблемы»

На присланном скриншоте **Astra AI HTTP 401**. AI endpoint отклонил авторизацию; это не ошибка Kubernetes и не доказательство неисправности qwen. Возможны истёкший/неподходящий токен или неверное значение Authorization. По одному 401 нельзя установить, какой именно случай произошёл.

## Исправить авторизацию без обновления

1. Откройте **Настройки → PeopleHub → Настроить → ИИ Astra**.
2. Проверьте полный AI URL: `http://10.128.77.23/api/v1/settings/ai/request/chat/completions`, model `qwen`.
3. Введите действующий Bearer token, которому Astra разрешает AI endpoint. Токены логов Astra и Kubernetes — отдельные подключения. Токен вводите только в защищённые настройки Pulse, не в чат и не в публичную команду curl.
4. Сохраните кластер, заново откройте настройки и нажмите **Проверить поток Astra AI**. Нужен завершённый ответ без 401.

Вместо Astra AI можно снять **Использовать ИИ Astra для этого кластера**, сохранить и использовать существующую локальную LLM. В глобальных настройках должны быть `http://127.0.0.1:8002/v1`, model `qwen`; **Проверить ответ** должен завершиться успешно. Не меняйте работающие подключения метрик и логов.

## Что меняет патч

- Для 401/403 показано точное действие по авторизации. Вставленный `Bearer <token>` нормализуется в один заголовок, в том числе для ранее сохранённого значения. Токен логов не заменяет AI key.
- Проверенные данные выбранного Pod видны сразу после сбора и сохраняются при отказе/обрыве ИИ; ошибка модели не уничтожает факты. Недоступные проверки названы явно.
- В окне выбранной проблемы есть **Движок анализа** и **Проверить ИИ**. После 401 доступен **Повторить через локальную LLM**: новый временный диалог по тому же объекту. Общие настройки кластера не меняются, скрытого fallback нет, сбор логов Astra остаётся отдельным источником.
- Для `Evicted: Usage of EmptyDir volume "data" exceeds the limit "1Gi"` Pulse отдельно показывает подтверждённое превышение лимита этого тома. Модель получает это доказательство и сценарий eviction. Проверяется, не пропущены ли EmptyDir/том/лимит и не выдуманы ли ссылки E##. При пропуске есть предупреждение; это ограниченная проверка, не сертификат правильности всего ответа.
- Закрытие окна по-прежнему удаляет временный диалог. Обзор, метрики и схема данных не меняются.

## Применить 0.14.1 с сохранением текущего runtime

Скачайте из приватного GitHub архив `releases/pulse-clusters-0.14.1-complete.tar.gz` и соседний `.sha256`, передайте оба в `/home/dito` на сервер Pulse. Команды ниже выполняются от root. Runtime используется тот же: без переноса данных и перенастройки метрик/LLM/Astra.

```bash
(
set -eu
umask 077
pulse_old_dir="$(docker inspect pulse-clusters-8090-pulse-1 --format '{{ index .Config.Labels "com.docker.compose.project.working_dir" }}')"
pulse_runtime="$(docker inspect pulse-clusters-8090-pulse-1 --format '{{range .Mounts}}{{if eq .Destination "/runtime"}}{{.Source}}{{end}}{{end}}')"
test -f "$pulse_old_dir/pulse"
test -f "$pulse_runtime/registry.key"
cd /home/dito
sha256sum -c pulse-clusters-0.14.1-complete.tar.gz.sha256
tar --keep-old-files -xzf pulse-clusters-0.14.1-complete.tar.gz -C /opt
cd /opt/pulse-clusters-0.14.1
sha256sum -c MANIFEST.sha256
./pulse --runtime "$pulse_runtime" build
pulse_backup_dir="/root/pulse-backup-0141-$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 "$pulse_backup_dir"
printf '%s\n%s\n' "$pulse_old_dir" "$pulse_runtime" > "$pulse_backup_dir/previous-paths.txt"
"$pulse_old_dir/pulse" --runtime "$pulse_runtime" backup --output-dir "$pulse_backup_dir"
"$pulse_old_dir/pulse" --runtime "$pulse_runtime" stop
./pulse --runtime "$pulse_runtime" start-offline
./pulse --runtime "$pulse_runtime" check
printf 'Backup: %s\nRuntime: %s\n' "$pulse_backup_dir" "$pulse_runtime"
)
```

Если каталог 0.14.1 уже распакован, не повторяйте распаковку поверх него; проверьте MANIFEST и продолжите с незавершённого шага. При ошибке не удаляйте runtime. Откат: остановить новый контейнер и запустить прежний `pulse --runtime <тот же путь> start-offline` по путям из `previous-paths.txt`. Существующие DNS/reverse proxy и порт остаются прежними.

Точная сборка: **0.14.1 / 933ba570cddbefd6**. Она также публикуется в **RELEASE.json** внутри архива и `/healthz`; `./pulse check` проверяет её совпадение с исходниками. После обновления нажмите **Ctrl+F5**.

## Проверить только вашу проблему

1. Откройте ✧ у проблемного Pod, выберите **Локальная LLM напрямую**, нажмите **Проверить ИИ**. Успех доказывает авторизацию и завершение ответа, не правильность диагноза.
2. Нажмите **Причины**. В проверенных данных должны быть именно выбранные namespace/name/UID, фактический узел и status.message. Если старый Pod удалён или UID изменился, это должно быть указано; новый Pod не должен выдаваться за старый.
3. Если сообщение всё ещё содержит превышение `EmptyDir data 1Gi`, ответ должен назвать это причиной завершения. Почему росли файлы, установлено только при наличии соответствующих логов/конфигурации. Это нельзя подменять OOMKilled, HPA или предположением о заполнении всего диска.
4. Раскройте журнал: недоступные логи/метрики не считаются проверенными. Наличие здоровой замены и влияние на сервис должны подтверждаться отдельными данными, а не одним Failed Pod.
5. Ответ без ссылок на журнал, с неизвестными E## или с пропуском явной причины получит предупреждение. Полнота оценивается по доказательствам именно этой ошибки. При обрыве/лимите токенов статус не становится «Ответ получен».

Никакие исправления в Kubernetes автоматически не выполняются. Уже работающие разделы повторно проверять не нужно.
