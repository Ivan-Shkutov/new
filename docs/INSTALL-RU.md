# Pulse Clusters 0.9.0: установка с нуля

Для действующей установки 0.8.0 используйте [обновление с сохранением данных](UPDATE-0.9.0-RU.md). Отдельное подключение HolmesGPT описано в [HOLMES-RU](HOLMES-RU.md).

Это самостоятельная реализация проекта. Архив 0.5.0 и его исходники не были предоставлены. Старые документы в `docs/imported` сохранены для контекста; их команды импорта 0.4/0.5, Holmes, AURA, PostgreSQL и Qdrant к этому выпуску не относятся. Для Holmes используйте только новую инструкцию выше. Не запускайте две версии на одном runtime.

## Требования

Основной сценарий: Linux, Docker Engine и Compose plugin с поддержкой `up --wait` (v2 и новее), Python 3.12+ для CLI и восстановления резервных копий, Git. Контейнер использует Python 3.12. Для начала достаточно 2–4 vCPU и 4 GiB RAM без учёта GPU/vLLM; это ориентир, не подтверждённый предел нагрузки. Нужны место под SQLite, документы и резервные копии, а также доступ с сервера к API кластеров и выбранным источникам.

Панель содержит инвентарь и диагностику; Kubernetes, Astra, Prometheus и vLLM устанавливаются отдельно. Без настроенного кластера стартует рабочая пустая панель, без модели инвентарь доступен, а LLM-анализ явно сообщает о недостающей настройке. Программа не подменяет интеграции демонстрационными данными.

Основной Docker-сценарий использует Linux host networking. В нём `127.0.0.1:8002` действительно обозначает vLLM на сервере. Windows используется как SSH-клиент; установка напрямую в Windows Docker Desktop не является проверенным сценарием.

## 1. Получить код и подготовить runtime

На сервере под отдельным пользователем с правами доступа к Docker:

```bash
git clone https://github.com/Ivan-Shkutov/new.git pulse-clusters
cd pulse-clusters
./pulse init --port 8090
```

Для приватного репозитория используйте настроенную GitHub-аутентификацию своей рабочей станции/сервера. Токен не вставляйте в URL и не сохраняйте в проекте. Можно перенести checkout с доверенной машины по SSH.

`init` создаёт `runtime/.env`, случайный пароль и ключ шифрования `runtime/registry.key`. Повторный вызов сохраняет существующие значения и документы. Перед сменой порта сначала выполните `./pulse stop` со старым значением, затем измените `PULSE_PORT` в `runtime/.env` и выполните `./pulse start-offline`. Имя Compose-проекта зависит от порта.

Права файлов закрыты для посторонних пользователей. При установке от root контейнер работает от UID/GID 65532; при обычном пользователе — от его числовых UID/GID, без root внутри контейнера. Не используйте `chmod -R 777`. Не меняйте вручную UID/GID уже работающего runtime без переноса владельцев файлов.

## 2. Собрать и запустить

```bash
docker version
docker compose version
./pulse start
./pulse status
./pulse check
```

Первая сборка требует доступ к Docker Hub и Python package index. Зависимости приложения перечислены в репозитории; Архив complete включает wheelhouse для Linux amd64 / CPython 3.12; при его наличии Docker устанавливает зависимости без обращения к PyPI. Git checkout без wheelhouse скачивает зависимости. GPU-весов в поставке нет. Базовый образ по умолчанию закреплён digest в Dockerfile и Compose. Для замены на другую одобренную базу перед сборкой добавьте в `runtime/.env` одобренный `PYTHON_BASE_IMAGE=python:3.12-slim@sha256:ФАКТИЧЕСКИЙ_DIGEST`. Не копируйте placeholder и не отключайте проверку TLS.

Контейнер запускается с read-only файловой системой, writable runtime и временным `/tmp`, без Linux capabilities и без Docker socket. Порт слушает только `127.0.0.1`. `check` проверяет HTTP процесса и аутентифицированный обзор, но не утверждает, что источники и качество диагностики проверены.

Пароль смотрит только оператор сервера:

```bash
cat runtime/secrets/portal-password
```

Логин по умолчанию — `pulse`. Пароль не отправляйте в чат и не коммитьте. Для замены запишите новый длинный случайный пароль в тот же файл и перезапустите приложение, сохранив владельца и режим 0600. Basic Auth требует TLS или SSH-туннель; приложение не предназначено для открытого HTTP в сети.

Windows PowerShell, отдельное окно:

```powershell
ssh -N -L 8090:127.0.0.1:8090 USER@SERVER
```

Откройте локальный порт 8090 в браузере. Для постоянного доступа нескольких операторов поставьте свой HTTPS reverse proxy перед localhost. В этом выпуске один административный аккаунт: не считайте его системой разграничения ролей нескольких пользователей.

## 3. Kubernetes

На доверенной административной машине сначала проверьте context, затем примените ограниченные права:

```bash
kubectl config current-context
kubectl apply -f deploy/rbac-readonly.yaml
kubectl auth can-i list pods --all-namespaces --as=system:serviceaccount:pulse-observer:pulse-reader
kubectl auth can-i get secrets --all-namespaces --as=system:serviceaccount:pulse-observer:pulse-reader
```

Последняя команда должна ответить `no`. ClusterRole не разрешает чтение Secret, exec или изменение workload. Технически право чтения ConfigMap разрешает API вернуть значения; приложение должно исключать их из сохраняемого инвентаря. Чтение логов также может раскрывать чувствительные данные; подключайте только согласованные источники.

Получить standalone kubeconfig с краткосрочным токеном:

```bash
python3 scripts/export-kubeconfig.py \
  --context "$(kubectl config current-context)" \
  --duration 24h \
  --output peoplehub-reader.json
```

Если API endpoint из административного kubeconfig недоступен с сервера Pulse, добавьте `--server https://ДОСТУПНЫЙ-API:6443`; имя должно соответствовать TLS-сертификату. Скрипт не копирует admin credential, а запрашивает токен `pulse-reader`. Фактический срок токена может быть короче запрошенного; организуйте обновление до истечения. Автоматической ротации Kubernetes credential этот выпуск не обещает.

В панели создайте кластер с уникальным ID, названием и содержимым reader kubeconfig. При замене загрузите новый файл в настройках. Не используйте admin kubeconfig. ClusterIP, Service DNS и приватный API не становятся доступны автоматически: настройте маршрутизацию/VPN или согласованный endpoint.

## 4. Источники и локальная модель

В настройках кластера задайте доступный Prometheus/VictoriaMetrics URL, авторизацию при необходимости и точные метки для ограничения выбранным кластером. Пустая выдача не означает нулевое потребление. Используйте реальные имена labels из источника.

Для Astra укажите URL, сервисный bearer token и поля cluster/namespace/pod из реальных логов. Контракт зависит от вашей установленной версии; сначала проверьте запрос в тестовом контуре. Чужие записи должны отфильтровываться точным совпадением меток; ограниченная выборка не доказывает отсутствие ошибок.

Для модели укажите доступный OpenAI-compatible vLLM URL (например, `http://127.0.0.1:8002/v1`), точный model ID и API key, если он нужен. Установка vLLM, NVIDIA-драйверов и весов модели выполняется отдельно. В этом выпуске Pulse формирует контекст из доступных фактов и запрашивает ответ модели; автономного выполнения произвольных команд и исправлений нет.

Проверьте на известном инциденте, что объяснение основано на фактах, а недостаток данных обозначен. Успешный health модели не равен правильному диагнозу.

## 5. Проверка после установки

1. Сопоставьте числа узлов/Pod/namespaces с `kubectl` с учётом времени снимка.
2. Убедитесь, что ошибки прав, недоступность источника и устаревшие данные видны.
3. Проверьте логи конкретного Pod и отсутствие строк соседнего кластера с таким же именем.
4. Загрузите тестовый документ без секретов, найдите его по уникальной фразе.
5. Запустите расследование, перезагрузите страницу и проверьте сохранение истории.
6. Запишите подтверждённое решение после фактической проверки оператором.
7. Сделайте backup и отрепетируйте restore на отдельной тестовой установке.

Не создавайте аварии в production для проверки модели. Используйте тестовый кластер или обезличенные записи.

## 6. Остановка и резервные копии

```bash
./pulse logs
./pulse stop
./pulse start-offline
./pulse backup --output-dir /ЗАЩИЩЁННЫЙ/КАТАЛОГ
```

Backup останавливает только контейнер текущего Compose-проекта, проверяет SQLite и создаёт архив runtime + внешнюю SHA256; затем возвращает ранее работающий контейнер. Локальный `./pulse dev` предварительно остановите: активный controller lock блокирует копирование. Копия содержит пароль, ключ расшифрования и подключения, поэтому храните её зашифрованно с ограниченным доступом вне сервера. SHA256 не заменяет подтверждение происхождения файла.

Восстановление требует соседнего `.sha256`:

```bash
./pulse restore /ПУТЬ/pulse-ДАТА.tar.gz --confirm-restore
./pulse start-offline
./pulse check
```

Проверяются checksum, типы и пути членов архива, объём распаковки и SQLite integrity. Старый runtime сохраняется в `runtime.before-ДАТА`. После успешного restore приложение остаётся остановленным до явного запуска; автоматического удаления прежних данных нет. Параметры порта и пароль восстанавливаются из копии. У этой версии Basic Auth нет серверных OIDC-сессий.

Планируйте срок хранения истории, загрузок и backup и контролируйте свободный диск. Автоматическая политика очистки в этом выпуске не заявлена. Все команды Compose ограничены проектом текущего порта; не меняйте порт перед остановкой уже работающего проекта.

## 7. Закрытый контур

На разрешённой Linux-машине той же архитектуры соберите и экспортируйте образ:

```bash
./pulse init
./pulse build
./pulse export-image /data/pulse-clusters-0.9.0.tar
```

Перенесите checkout, образ и его `.sha256` в закрытый контур. Не переносите рабочий runtime, если это новая установка.

```bash
sha256sum -c pulse-clusters-0.9.0.tar.sha256
docker load --input pulse-clusters-0.9.0.tar
cd pulse-clusters
./pulse init --port 8090
./pulse start-offline
./pulse check
```

Docker Engine, Compose, Git/Python и внешние интеграции готовятся отдельно. Образ vLLM и веса не входят в образ Pulse. Встроенная база `python:3.12-slim` не требуется на целевой машине при переносе уже собранного полного образа приложения.

## 8. Разработка без контейнера

```bash
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.txt
./pulse init
./pulse dev
```

`dev` использует `.venv/bin/python`, если он существует. Для тестов установите `requirements-dev.txt` согласно README. Не запускайте второй процесс на том же runtime; SQLite и background collector обслуживает один процесс.

`./pulse --help` показывает доступные команды. Перенос runtime 0.8.0 выполняется штатным backup/restore. Автоматический импорт установок 0.4/0.5 не поддерживается: формат совместимости не подтверждён без их исходников и образцов.


## 9. Установка из приложенного архива

Скачайте `pulse-clusters-0.9.0-complete.tar.gz` и соседний `.sha256` из `releases` репозитория. На Linux в каталоге загрузок:

```bash
sha256sum -c pulse-clusters-0.9.0-complete.tar.gz.sha256
mkdir -p ~/apps
tar -xzf pulse-clusters-0.9.0-complete.tar.gz -C ~/apps
cd ~/apps/pulse-clusters-0.9.0
./pulse init --port 8090
./pulse start
./pulse check
```

Распаковывайте в новый каталог обычным пользователем. Архив не содержит runtime, паролей, баз истории и пользовательских подключений. Wheelhouse проверен для Linux amd64/Python 3.12. Для другой архитектуры используйте Git checkout и онлайн-сборку; этот вариант не проверен здесь. Для сборки всё равно нужен базовый Docker-образ; полностью изолированный сервер требует заранее экспортированного образа по разделу 7.

## 10. Если на сервере ещё нет Docker

Выберите инструкции для своей ОС на https://docs.docker.com/engine/install/ и установите Docker Engine и Compose plugin из официального репозитория. Для Ubuntu 24.04 Python 3.12 входит в штатные пакеты: `sudo apt-get update` и `sudo apt-get install -y python3 git`. Затем проверьте `python3 --version`, `docker version`, `docker compose version`. На RED OS используйте одобренный вашей организацией источник Docker/Compose; команды Ubuntu к RED OS не применяются. Пользователю требуется право работать с Docker либо запуск команд установки через sudo. Не выполняйте случайные install-скрипты и не отключайте TLS.

## 11. Настройка модели и документов

Откройте «Настройки», введите URL уже работающего vLLM, model ID и при необходимости API key; сохраните и нажмите «Проверить ответ». При отсутствии GPU-сервера можно использовать другой доверенный OpenAI-compatible endpoint, учитывая, что туда будут отправляться выбранные наблюдения и документы. Поставка Pulse не устанавливает модельный сервер: требуемые веса и параметры зависят от GPU и лицензии модели.

В «Базе знаний» загрузите описание приложения без секретов. Выберите кластер для ограничения документа этим подключением; без выбора документ общий. Выполните поиск по уникальному слову. В «Ресурсах» выберите Pod и задайте вопрос. После получения ответа можно продолжить расследование. Ответ модели является гипотезой; подтверждённое решение сохраняйте только после реального исправления и проверки.


## Обновление Git-установки

В каталоге существующей установки, до обновления:

```bash
./pulse backup --output-dir "$HOME/pulse-backups"
./pulse stop
git status --short
git pull --ff-only origin main
./pulse start
./pulse check
```

Продолжайте после каждой команды только при успешном завершении. Если `git status` показывает ваши изменения, сохраните и разберите их до pull. Не выполняйте reset/clean. Сохраните runtime и registry.key: повторный init не восстанавливает потерянный ключ. При потере ключа нужна исходная копия или полный backup. При обновлении установки из архива используйте новый каталог и восстановление штатного backup; не распаковывайте поверх runtime.

При смене URL модели/метрик/Astra ранее сохранённые credentials и CA больше не переносятся автоматически: введите их явно для нового адреса. Для того же адреса пустое поле сохраняет прежнее значение. Административный API поддерживает `clear_credentials: true` в настройках источника для явного удаления сохранённых credentials.
