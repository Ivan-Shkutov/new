# Контракты интеграций Pulse 0.6.1

Это новая реализация, а не восстановленный код 0.5.0. Адаптеры покрыты локальными тестами HTTP-контрактов. Совместимость с реальными серверами пользователя в этой работе не проверена.

## Kubernetes

Принимается автономный kubeconfig: HTTPS API, текущий context, bearer token либо встроенная пара client certificate/key, встроенный CA либо системные доверенные CA. Запрещены `exec`, `auth-provider`, ссылки на credential-файлы, impersonation, proxy/TLS name overrides и отключение TLS. Для kubeconfig с несколькими contexts API Python поддерживает явный выбор context.

Сбор выполняет read-only LIST 22 типов ресурсов, по 500 записей на страницу, максимум 4 страницы на тип. Прерывание, запрет и ограничение страниц показываются отдельно. Общий бюджет сбора — 45 секунд плюс завершение текущего запроса, timeout отдельного запроса — 10 секунд. Отказ одного типа не уничтожает уже собранные данные. `observed_at` обозначает начало цикла, а не атомарный снимок кластера.

Secret и exec не вызываются. Из снапшотов удаляются annotations/managedFields, значения `env`, аргументы и команды контейнеров. ConfigMap содержит только metadata и имена ключей. Это целевая редактировка распространённых источников секретов, а не гарантия отсутствия чувствительной информации во всех полях Kubernetes. Имена, статусы и произвольные сообщения upstream также могут содержать чувствительные данные.

Логи Pod — отдельный запрос: не более 500 строк и 256 KiB; поддержаны container и previous. В логах маскируются распространённые формы Bearer/Basic, password/token/secret/api_key, JWT, private key и credentials в URL. Это эвристики, а не универсальная очистка секретов: оператор отвечает за разрешённую область просмотра и передачу в модель.

## Prometheus/VictoriaMetrics

URL задаётся до `/api/v1/query`, например адрес vmauth с tenant path. Поддержаны bearer token, Basic либо доступ без аутентификации; собственный CA PEM. Если задан bearer token, он имеет приоритет перед Basic.

Выбор метрик ограничен идентификаторами: `cpu`, `memory`, `node_cpu`, `node_memory`, `filesystem`, `pvc_used`, `pvc_capacity`. Произвольный PromQL не исполняется. `cpu` — rate CPU seconds контейнеров, единица CPU cores; `memory` — рабочая память в bytes; `node_cpu` — суммарные non-idle CPU seconds/second по instance, не процент; `node_memory` — доступная память в bytes; `filesystem` — доступное место filesystem в bytes. PVC usage/capacity в bytes.

Для общего хранилища обязательны явные `labels`, например `{"cluster":"peoplehub"}`. Для источника, который обслуживает только один кластер, можно задать `mode: dedicated` без labels. Эти свойства источника должен проверить администратор. Пустой результат обозначается `empty: true`, а не нулевым потреблением. CPU container aggregation может включать инфраструктурные серии в зависимости от exporters; сверяйте labels и контрольные запросы перед интерпретацией.

## Astra

Реализован ограниченный HTTP-адаптер исторических логов `/api/v1/logs/search/monitorLogs`. Требуется сервисный bearer token; вход по паролю и автоматическое обновление токенов в этой версии не реализованы. API Astra меняется между версиями, поэтому перед использованием необходимо сопоставить payload `time/query/paging` и схему ответа со Swagger установленного сервера. Ответ неуспешного или неподдерживаемого контракта отображается как ошибка, без подстановки вымышленных логов.

Требуются точное поле и значение кластера, а также поля namespace/pod. Адаптер применяет точное сравнение к каждому результату после серверного поиска и не возвращает записи без совпадающего scope. До 4 страниц по 250 записей; признак `truncated` обозначает достижение лимита. Если нужные записи находятся за пределами просмотренного окна, пустой результат не доказывает отсутствие логов.

Этот модуль не реализует Astra incidents API, ClickHouse, внешние Holmes/AURA tools или совместимость со всеми версиями Astra.

## vLLM / OpenAI-compatible API

Используется POST `/v1/chat/completions`, точный model ID, до 1800 output tokens, температура 0.1, без stream. URL может включать `/v1`; bearer задаётся через `api_key` или `token`, свой CA — `ca_pem`. Timeout ответа — 90 секунд, соединения — 10 секунд.

В этой версии модель получает заранее собранный контекст и возвращает текст. Автономные tool calls, shell, SQL, запись в Kubernetes и внешние агенты не включены. Сообщения ограничены 60 элементами и суммарно 150000 символами; это символьный предохранитель, а не гарантированное соответствие tokenizer/context конкретной модели. Настройте объём контекста с учётом модели. Модельный вывод — гипотеза оператора; он не подтверждает причину и не запускает исправления.

## Общая сеть и ошибки

HTTP redirects отключены, чтобы не переносить credentials на другой origin. Проверка TLS всегда включена. Переменные ambient proxy (`HTTP_PROXY`, `HTTPS_PROXY`) адаптерами не используются: маршруты должны обеспечивать прямую доступность источников. Поддержаны HTTP endpoints для локального vLLM/доверенной сети; при передаче credentials через внешнюю сеть используйте HTTPS.

Ответ ограничен 16 MiB на HTTP-запрос. Ошибки показывают HTTP-код либо безопасное описание, без upstream body, URL с credentials или токенов. Эти ограничения не заменяют сетевые ACL: администратор приложения определяет адреса источников, поэтому доступ к управлению подключениями должен быть строго ограничен.
