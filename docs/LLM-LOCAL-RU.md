# Локальная LLM для текущей установки Pulse

Пользователь подтвердил работу vLLM на 10.129.160.10 и успешный ответ из Pulse 29 октября 2026.

| Поле | Значение |
|---|---|
| Базовый URL в Pulse | `http://127.0.0.1:8002/v1` |
| Model ID | `qwen` |
| API key | Не потребовался в подтверждённой проверке |
| Контекст, сообщённый vLLM | 65536 токенов |
| Результат кнопки «Проверить ответ» | «Модель ответила: Понял.» |

Compose Pulse использует Linux host network, поэтому localhost относится к тому же серверу, где работает vLLM. Проверка на хосте:

```bash
curl --fail --silent --show-error http://127.0.0.1:8002/v1/models
```

В панели Настройки → ввести URL и Model ID → Сохранить → Проверить ответ. Наличие модели в списке и генерация ответа — две разные проверки. Если сервер в будущем требует авторизацию, задайте его ключ в защищённом поле формы; не передавайте ключ в чат или Git.

## Проверить анализ реальных данных

Выберите PeopleHub → Ресурсы → Pods → выберите известный Pod → Почему?. Проверьте namespace и Pod в форме расследования и отправьте вопрос. Пример: «Объясни текущее состояние этого Pod. Раздели наблюдения, гипотезы и недостающие данные. Если признаков сбоя нет, так и скажи.»

Убедитесь, что задание завершилось, ответ ссылается на реальные статусы/логи, нет выдуманных метрик и после обновления страницы история сохраняется. Продолжение обсуждения доступно у завершённого ответа. Наиболее полезная проверка качества — известный случай в тестовом окружении, с заранее установленной причиной.

Pulse 0.6.1 передаёт снимок и ограниченный контекст, документы и при выборе Pod его логи. Контекст в приложении ограничивается символами и не является точным tokenizer budget; значение 65536 не означает, что нужно заполнять весь лимит. Модель отвечает текстом, не исполняет команды или исправления; поддержка autonomous tool calling не проверяется этой кнопкой и не заявлена.

При таймауте проверьте занятость vLLM и время генерации. При 401 — его авторизацию. При отсутствии модели — точное поле id. Не перезапускайте работающую модель и не меняйте parser/chat template без конкретной ошибки. Для диагностики достаточно текста ошибки без credentials и внутренних логов с секретами.
