# Pulse 0.14.2 — достоверность метрик и доказательств ИИ

Точная сборка: **0.14.2 / 22aca541ffa83053**. Build ID идентифицирует код приложения, а не Docker image digest. Он должен совпасть в `/healthz`, `RELEASE.json` и выводе `./pulse check`.

## Исправления

- CPU/RAM/корневая ФС: проверка структуры ответа, чисел, времени, предупреждений Prometheus и соответствия экспортёров реальным Kubernetes nodes. Проверка выполняется и при обновлении Обзора, а не только при сохранении. Чужие, дублирующие один узел или отсутствующие источники не дают ложный общий процент.
- PromQL отбрасывает исходные samples старше 120 секунд **до** расчёта процентов. Это нужно потому, что timestamp результата вычисления может быть текущим даже при старых исходных данных. Общий процент учитывает размер ресурсов, а одинаковые scrape jobs не удваивают вес узла.
- Настройки подключения защищены от параллельной перезаписи; при конфликте возвращается понятный 409 и предложение обновить форму. После изменения очищается кеш метрик. Это устраняет найденный сценарий потери изменений, но не доказывает причину всех прошлых сбросов на сервере.
- Завершающийся Pod не становится зелёным; зависшее удаление отмечается отдельно. Все Pod остаются в общем количестве, Completed входит в здоровые только после проверки завершения контейнеров.
- Сценарий расследования выбирается после чтения фактической причины Pod. Большие metadata, запросы и результаты укладываются в бюджет контекста с явным признаком сокращения. Счётчики и идентификаторы доказательств сохраняются.
- Неполные страницы событий/объектов и обрезанные логи явно отмечаются. Отказ источника, неполный результат и завершённая проверка различаются.
- Для локального OpenAI-compatible API и Astra требуется `finish_reason=stop`. Обрыв, лимит токенов и явная ошибка Holmes сохраняют доступный текст как незавершённый ответ. Токен логов не подменяет ключ Astra AI.
- Ошибки записи и некорректные ответы Qdrant/embeddings не выдаются за успешную индексацию или отсутствие документов.

В [QA](QA-RU.md) записаны фактически выполненные проверки. Эти исправления не продлевают токен Astra, не настраивают недоступный сервер Prometheus и не гарантируют правильность произвольного вывода модели.

## Обновление с сохранением данных

Скачайте из приватного GitHub `releases/pulse-clusters-0.14.2-complete.tar.gz` и соседний `.sha256`, передайте оба в `/home/dito` на сервер Pulse. Команды рассчитаны на ранее подтверждённый контейнер `pulse-clusters-8090-pulse-1` и выполняются от root. Если имя изменилось, сначала найдите его через `docker ps` и замените в двух командах `inspect`.

Используется существующий runtime с его ключом и настройками. Не запускайте `init` поверх действующей установки.

```bash
(
set -eu
umask 077
pulse_old_dir="$(docker inspect pulse-clusters-8090-pulse-1 --format '{{ index .Config.Labels "com.docker.compose.project.working_dir" }}')"
pulse_runtime="$(docker inspect pulse-clusters-8090-pulse-1 --format '{{range .Mounts}}{{if eq .Destination "/runtime"}}{{.Source}}{{end}}{{end}}')"
test -f "$pulse_old_dir/pulse"
test -f "$pulse_runtime/registry.key"
cd /home/dito
sha256sum -c pulse-clusters-0.14.2-complete.tar.gz.sha256
tar --keep-old-files -xzf pulse-clusters-0.14.2-complete.tar.gz -C /opt
cd /opt/pulse-clusters-0.14.2
sha256sum -c MANIFEST.sha256
./pulse --runtime "$pulse_runtime" build
pulse_backup_dir="/root/pulse-backup-0142-$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 "$pulse_backup_dir"
printf '%s\n%s\n' "$pulse_old_dir" "$pulse_runtime" > "$pulse_backup_dir/previous-paths.txt"
"$pulse_old_dir/pulse" --runtime "$pulse_runtime" backup --output-dir "$pulse_backup_dir"
"$pulse_old_dir/pulse" --runtime "$pulse_runtime" stop
./pulse --runtime "$pulse_runtime" start-offline
./pulse --runtime "$pulse_runtime" check
printf 'Backup: %s\nRuntime: %s\n' "$pulse_backup_dir" "$pulse_runtime"
)
```

Wheelhouse в архиве предназначен для Linux amd64 / Python 3.12. Для сборки нужен базовый Python-образ, закреплённый digest в Dockerfile: в закрытой сети он должен быть уже загружен. Если каталог 0.14.2 уже есть, не распаковывайте поверх него: проверьте MANIFEST и продолжайте с незавершённого шага. Backup содержит учётные данные; храните его с ограниченным доступом.

Откат: остановите новый контейнер и запустите прежний `pulse --runtime <тот же путь> start-offline`, используя пути из `previous-paths.txt`. Схема данных в этом выпуске не менялась. Не удаляйте runtime. После обновления страницы нажмите **Ctrl+F5**.

## Короткая проверка вашей установки

Из каталога 0.14.2 с фактическим путём runtime:

```bash
./pulse --runtime /путь/к/действующему/runtime check
./pulse --runtime /путь/к/действующему/runtime doctor --cluster peoplehub
```

1. **Метрики:** нужны актуальные CPU/RAM/root filesystem для всех узлов. При ошибке смотрите конкретную причину/покрытие в диагностике источника. Для PeopleHub ранее найден сервис `monitoring/kube-prom-kube-prometheus-prometheus:9090`; выбранный transport и RBAC `get services/proxy` должны соответствовать фактической сети. Прямой ClusterIP с другого сервера не считается доступным автоматически.
2. **Чат:** запрос «выведи все pods, которые не Running» должен вернуть полный список Kubernetes с отдельным обозначением здоровых Completed и проблемных Pod. При неполном чтении API нельзя писать «проблем нет».
3. **Выбранная ошибка:** откройте ✧ и нажмите «Причины». У сверяемого Pod должны совпадать namespace/name/UID. Для известного `EmptyDir data 1Gi` причина выселения — превышение лимита тома; причины роста файлов нельзя объявлять установленными без дополнительных данных.
4. **ИИ:** «Проверить ИИ» подтверждает доступ и завершение ответа, а качество проверяется ссылками на журнал и отсутствием противоречий фактам. `Astra AI HTTP 401` требует действующего ключа Astra AI или явного выбора локальной модели; [инструкция](UPDATE-0.14.1-RU.md).
5. **Временный диалог:** закройте окно и снова откройте ✧ — история должна быть пустой. Переписка не записывается в постоянную историю Pulse; внешние LLM/Astra могут иметь собственную политику журналирования.

Если проверка не прошла, для следующего точечного исправления достаточно версии/build ID, вывода `doctor` и ошибки нужного источника без секретов. Повторять полный аудит остальных разделов не требуется.
