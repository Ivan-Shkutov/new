# Pulse: краткий контекст для следующей задачи

Обновлено 31.10.2026. Сверяйте с `git status`, кодом и сервером; этот файл заменяет пересказ истории, но не фактическую проверку.

- Только Pulse Clusters, репозиторий `Ivan-Shkutov/new`; Cloud/OpenStack — отдельный проект. FastAPI, статический UI, Docker Compose, локальный runtime с шифрованными подключениями.
- Исходники: **0.14.2 / build 22aca541ffa83053**. Инструкция: [UPDATE-0.14.2-RU.md](UPDATE-0.14.2-RU.md). Последняя подтверждённая пользователем серверная версия — **0.13.0**; развёртывание 0.14.2 не подтверждено. Не выбирать каталог `/opt` по старой истории: выяснять runtime активного контейнера.
- Источники: Kubernetes reader kubeconfig, Prometheus/VictoriaMetrics, Astra logs; AI: локальная OpenAI-compatible Qwen/vLLM, опционально HolmesGPT или Astra AI; RAG: Qdrant + embeddings. Название `qwen` — served model ID, точные веса/квантизацию сверять с сервером. Документация VK и доступность частных сервисов не доказаны этой средой.
- Подтверждённая проблема PeopleHub: `am-agent/am-agent-am-agent-deployment-8d6ddf79-lwzwg` Evicted, `Usage of EmptyDir volume "data" exceeds the limit "1Gi"`. Это причина выселения; причина роста файлов требует собственных доказательств. Не подменять её OOMKilled/HPA/заполнением всего узла.
- `Astra AI HTTP 401` — проблема авторизации AI endpoint. Логи Astra и Astra AI используют отдельные настройки. Код сохраняет факты при отказе и предлагает явный local retry. Не утверждать, что обновление кода исправило истёкший токен.
- 0.14.2: проверка структуры/свежести метрик, raw sample gate в PromQL, соответствия exporter→Node при обновлении; защита от параллельной перезаписи настроек; завершение Pod не зелёное по умолчанию; сценарий выбирается из live Pod; bounded JSON для ИИ; частичные доказательства маркируются; явное завершение LLM/Astra; ошибки Qdrant не маскируются пустой выдачей/успешной индексацией.
- Проверено локально: **306 pytest**, **24 настоящих вычисления PromQL**, **4 Chromium-сценария** (метрики/список Pod, 401/local retry, временные чаты, компактный Обзор), Docker build/start/check, JS и 3 Compose. Подробности/границы: [QA-RU.md](QA-RU.md). Тестовые upstreams не доказывают работу настоящих PeopleHub, Astra, Qwen или Holmes. Следующий шаг на сервере: `./pulse check`, `./pulse doctor --cluster peoplehub`, один контрольный инцидент.
- UX: компактный тёмный Обзор (узлы/все здоровые Pod/сигналы, CPU/RAM/диски, 7 workloads, проблемы); детали по нажатию. ✧ открывает временный диалог, закрытие очищает его; отдельный общий чат. Kubernetes остаётся read-only. История постоянных расследований — отдельная функция.
- Качество ИИ: факты с cluster/namespace/name/UID, временем и E##, отдельно гипотезы и недоступные проверки. Ответ «завершён» не означает «доказан». Проверка ссылок/EmptyDir ограниченная, не универсальный валидатор истины.
- Развитие Holmes через Kubernetes skills/tools/MCP желательно, но присланный пользователем extension kit не считается установленным. Не повторять широкий аудит и не подключать все инструменты ради одной ошибки.

Начало задачи: `git status --short --branch` → соответствующий модуль и `tests/test_<модуль>.py`. Точечная проверка: `.venv/bin/python -m pytest -q tests/<файл>.py`. Полный pytest/сборка/браузер нужны для сквозного изменения или выпуска. Для PromQL есть `scripts/promql-smoke.py` (promtool или заранее загруженный Docker image); настройки CI в `.github/workflows/tests.yml`. Секреты/runtime не читать в чат и не коммитить.

Для экономии используйте [CODEX-WORKFLOW-RU.md](CODEX-WORKFLOW-RU.md) и шаблон GitHub issue. Достаточно этого файла и связанных участков кода; перечитывать все старые release-документы и длинную переписку не нужно. Markdown не отменяет квоты и не обеспечивает память вне репозитория.
