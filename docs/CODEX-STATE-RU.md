- Проект: только Pulse Clusters, приватный `Ivan-Shkutov/new`. Cloud/OpenStack — отдельный проект. FastAPI, статический UI, Docker Compose, шифрованный локальный runtime.

- Основной экран `#diagnostics`: **Краткий разбор, Подробный разбор, Причины сбоя, Последствия сбоя, План устранения, Проверка восстановления**. Слева кнопки, справа один заменяемый короткий результат, источники закрыты. Предыдущий ответ модели не передаётся следующей кнопке. Фото рабочего тестового стенда: `docs/images/scenarios-0151/`; первоначальный макет сохранён в `design/scenario-workflows/`.
- Новый API: `GET /api/scenarios`, `POST /api/sessions/{sid}/scenarios`. Только фиксированный scenario и точная цель; произвольный question/previous_id/engine override отвергаются. Сессия привязана к cluster/namespace/name/UID и digest настроек источников, включая LLM. Смена конфигурации во время проверки исключает актуальный/verified результат. Последние задания ограничены в RAM; постоянной истории новых сценариев нет.
- Совместимые старые `/sessions/{sid}/messages`, `/investigations`, `#chat` оставлены для старых клиентов/CLI. В основной навигации чат заменён диагностикой; прежние сохранённые расследования доступны как архив. Не смешивать legacy transcript и новый scenario DTO.
- Карта: `app.py` — API/worker; `sessions.py` — volatile state; `diagnostics.py` — шесть ограниченных планов Pod; `resource_diagnostics.py` — Node/контроллеры/PVC и CPU/RAM/disk; `workflows.py` — канонический DTO, строгая схема дополнения модели, команды и вердикт восстановления; `static/scenarios.js/css` — UI. Тесты: `test_scenario_api`, `test_diagnostic_profiles`, `test_resource_diagnostics`, `test_workflows`.
- Подтверждённые факты, причина из статуса, техническая важность и команды формируются Pulse. Модель получает BASE/KUBERNETES/релевантный NETWORK + runbooks и возвращает только JSON `{hypotheses, checks}`. Ссылки/размер/форма проверяются, семантическая точность не гарантируется. Невалидный JSON или ошибка модели оставляет факты и журнал, raw draft в основной результат не попадает. Применённые rules/skills и tools доступны в закрытых источниках.
- В 0.15.1: policy senior-devops v2 дополнена по ошибкам настоящей Qwen; новые сценарии отвергают известные текстовые инструкции изменить инфраструктуру, команды по-прежнему только канонические. Для current OOM читаются текущие логи, для lastState — previous; цели Service требуют собственного evidence_id. `scripts/upgrade-existing.py` проверяет MANIFEST и Docker build, определяет runtime из контейнера, делает backup и rollback. Complete-архив включает готовый Docker-образ amd64; сборка и registry для установки не нужны при наличии Docker/Compose/Python.
- Прямые Pod-сигналы: EmptyDir eviction, OOMKilled current/last, CrashLoop, ImagePull, same-UID FailedScheduling/probe. Это не автоматически доказанная первопричина приложения. Команды только read-only, shell/exec/исправления автоматически не запускаются.
- Recovery не вызывает LLM/KB. Требуются свежий owner UID/observedGeneration, полный список готовых реплик владельца и endpoints с targetRef UID этих Pod. Cached Pod может связать старую идентичность с владельцем, но не подтвердить текущее состояние. Ready/endpoints не доказывают внешний пользовательский запрос или отсутствие повторений за период. Для non-Pod полного вердикта восстановления приложения нет.
- Pod-бюджеты сбора 35/90/75/35/70/45 с для brief/deep/causes/impact/plan/recovery; остальные ресурсы 30 с. Общий deadline передаётся HTTP/logs/metrics/Astra pagination. Неполные списки и недоступные источники явные. Metric scope и свежесть сверяются с live Nodes. Отмена сессии отбрасывает поздний результат, но уже начатая внешняя генерация может идти до timeout.
- Проверка исходников: **529 pytest прошли**, один warning устаревшего Starlette TestClient. Docker Linux amd64/Python 3.12.16 совпал с идентичностью исходников; локальный Python 3.12.14. Девять браузерных сценариев, 24 PromQL-вычисления, реальный 0.14.4→0.15.1 backup/restore, автоматическое обновление из готового комплекта и созданный откат обратно на 0.14.4 прошли; детали в QA. Fixtures не доказывают качество настоящей модели или доступ к частным сервисам.
