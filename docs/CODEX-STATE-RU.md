# Краткий контекст Pulse для нового чата

Обновлено: 31.10.2026. Этот файл помогает продолжить работу без длинной истории; факты ниже нужно сверять с актуальным кодом и сервером.

- Репозиторий: `Ivan-Shkutov/new`, приложение Pulse Clusters, FastAPI + статический UI, Docker Compose, локальный runtime. Версия исходников при записи: **0.14.1** (`pulse_app/__init__.py`). Это не подтверждение версии на сервере пользователя.
- Источники: Kubernetes reader kubeconfig, Prometheus/VictoriaMetrics, логи Astra. Анализ: локальная OpenAI-compatible LLM (`qwen` через vLLM), опционально HolmesGPT или Astra AI; знания и документы через Qdrant.
- Последний подтверждённый пользователем серверный `/healthz`: **0.13.0**. Возможны обновления после этого сообщения; всегда проверяйте фактический `/healthz`, build ID и источник метрик.
- Известный конкретный случай PeopleHub: Pod `am-agent-am-agent-deployment-8d6ddf79-lwzwg` в `am-agent` Evicted; в представленном status.message есть `Usage of EmptyDir volume "data" exceeds the limit "1Gi"`. Эта причина выселения подтверждена сообщением Pod; причина роста данных внутри EmptyDir требует отдельных доказательств.
- Пользователь видел `Astra AI HTTP 401` при анализе. Исходники 0.14.1 добавили пояснение, сохранение доказательств и явный повтор через локальную модель. Действующий токен Astra и его права в этой среде не проверены.
- Пользователь наблюдал отсутствие CPU/RAM/дисков и сброс настроек метрик. Исходники 0.14.0 добавили проверку источника и чтение обратно, но работа именно с его Prometheus после развёртывания не подтверждена. Проверять `./pulse doctor --cluster peoplehub` и реальные данные выбранного источника.
- Обзор должен показывать все Pod, включая здоровые завершённые, и подсвечивать подтверждённые ошибки; метрики должны показывать покрытие узлов, устаревшие данные и ошибки источника.
- Выбранный интерфейс — компактный Pulse Dark: на одном экране здоровье узлов/Pod/сигналов, круговые CPU/RAM/диски, семь workloads и список проблем; детали открываются по нажатию. У анализа проблемы временный диалог, при закрытии он очищается; отдельный чат с ИИ предусмотрен.
- Пользователь хочет развивать HolmesGPT через специализированные Kubernetes skills, tools и при необходимости MCP для Pulse/Astra/Qdrant. Присланное описание стартового комплекта не доказывает, что этот комплект установлен или испытан на его сервере; реальные подключения надо проверять отдельно.
- Главный запрос пользователя: точный диагноз с журналом проверок, логами/событиями/метриками и понятным объяснением, как обнаружена причина. Модель не должна выдавать общие предположения как подтверждённые факты.
- Предыдущая попытка широкого параллельного аудита прервалась из-за лимита использования; агенты сообщили о возможных дефектах разбора Prometheus JSON, давности метрик, покрытия узлов и ограничения контекста ИИ. Эти сообщения — задачи для проверки, а не выполненные исправления.

Команды для точечной работы: `git status --short --branch`; `.venv/bin/python -m pytest -q tests/<нужный_модуль>.py`; для готового выпуска `.venv/bin/python -m pytest -q`. Живые проверки выполняются на сервере пользователя после обновления: `./pulse check`, `./pulse doctor --cluster peoplehub`. Не объявлять реальную интеграцию исправной по локальным mocks.
