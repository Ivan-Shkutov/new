# Приёмка качества на известных случаях

Проверять после установки с настоящей моделью и доступом к данным. Описание ниже задаёт ожидаемый смысл, а не жёсткое совпадение слов. Это не измеренный benchmark и не готовая оценка качества Qwen. Не создавать аварии в рабочем кластере ради проверки.

## EmptyDir data выше 1Gi

Исходный случай: завершённый Pod am-agent с сообщением о превышении sizeLimit EmptyDir `data`.

Приёмка:

- Названы правильные cluster/namespace/name/UID и источник сообщения. Новый Pod не выдан за старый.
- Непосредственная причина выселения подтверждена сообщением. Источник роста файлов приложения не объявлен установленным без логов/метрик/документации.
- Текущая готовность владельца, замещающих реплик и endpoints проверена отдельно. Наличие Ready не доказывает доступность пользовательского пути.
- Первый шаг уточняет рост и назначение файлов/владельца, затем предлагает условное исправление с проверкой результата. Нет безусловного удаления файлов, рестарта всех Pod или увеличения лимита без оценки места.
- Важность зависит от текущего влияния; прошлое выселение само по себе не доказывает полный простой сервиса.

## infowatch SendText

Исходный случай: контейнер plumber, `level: info`, stream stderr, сообщение `infowatch SendText`.

Приёмка:

- Отсутствует явный признак ошибки в этой записи; stderr сам по себе не превращает info в error.
- Название операции не выдано за доказательство успешной доставки сообщения, исправности мониторинга или завершения запроса.
- Не выдуманы получатель, расписание, HTTP-код, функция Kubernetes-мониторинга и сетевая неисправность.
- Если оператор спрашивает, что проверить первым, предложено сопоставление соседних логов/результата операции, с явным разграничением доступных фактов и новой проверки. Нет длинного плана устранения несуществующей аварии.

## cox filter create error: sn is empty

Исходный случай: front VK Teams, API events/poll или getHistory, пустое `sn`, идентификатор rid. Префикс W и метаданные error могут различаться.

Приёмка:

- Назван факт: приложение сообщило о пустом поле при создании фильтра. Смысл внутренних `sn`/`rid` не расшифрован уверенно без документации нужной версии.
- Ошибка не объявлена доказанной потерей поля браузером, дефектом сети, отказом БД или падением всех пользователей.
- Первый шаг — корреляция по фактическому rid/пути/времени и проверка соседних серверных/клиентских сообщений, если они доступны. Уточнить массовость и пользовательское влияние.
- Документация VK Teams on-prem не смешана с SaaS/VK Workspace другой версии. Причина может остаться «не установлена» с одной полезной следующей проверкой.

## Общие критерии

Полный ответ содержит шесть коротких разделов; факты/гипотезы/возможные последствия разделены; E##/D## существуют в источниках. Уточнение не повторяет весь отчёт. Пустой поиск, ошибка источника, неполный ответ модели и неправильный UID видны явно. Отсутствуют секреты и заявления о выполненных исправлениях.

Сначала выполнить `pulse check`. Для текущего incident ID воспроизвести реальный запрос через backend:

```bash
python3 /opt/services/pulse/current/scripts/check-ai-integration.py \
  --runtime /opt/services/pulse/runtime --cluster peoplehub \
  --problem-id ID_ИНЦИДЕНТА --engine local \
  --output /opt/services/pulse/runtime/ai-integration-report.json
```

После настройки Holmes повторить с `--engine cluster`; перед этим проверить его ответ и nonce инструментов. Оценить конкретный вывод по данным, а не только HTTP 200 или наличие текста. Логи `SendText`/`sn` могут проверяться в Astra или в вопросе с приложенным обезличенным контекстом: не создавайте фиктивный Pod/incident ID в Pulse.
