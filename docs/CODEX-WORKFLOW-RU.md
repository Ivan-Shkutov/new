# Как экономно работать с Codex над Pulse

Файлы `AGENTS.md` и `docs/CODEX-STATE-RU.md` позволяют новому чату узнать правила и текущее состояние проекта без пересказа всей истории. Короткая история сама по себе не увеличивает лимит использования; она уменьшает объём повторных объяснений и ненужных проверок. После каждого завершённого этапа обновляйте состояние в одном месте.

## Рабочий ритм

1. Ставьте одну измеримую задачу: симптом, кластер/объект, ожидаемый результат и способ проверки. Например: «PeopleHub, 6 узлов, CPU/RAM/диски показывают “Нет данных”; найди причину в подключении Prometheus, исправь, проверь тестами и сообщи точную команду проверки на сервере».
2. Просите сначала читать связанные модули и их тесты. Полный аудит всех файлов нужен перед выпуском или при сквозном дефекте; для отдельного 401 он тратит время и контекст без пользы.
3. Просите исправление и проверку, а не только план. Приёмка должна включать конкретный запрос/API/скрин или тестовый сценарий, где ошибка исчезла.
4. На границе этапа фиксируйте коммит, версию, подтверждённые результаты и оставшиеся проблемы в `CODEX-STATE-RU.md`. Новый чат пусть читает этот файл и нужные части кода.
5. Используйте одну активную задачу или немного независимых задач. Несколько параллельных агентов расходуют общий лимит быстрее; в предыдущем широком аудите агенты остановились по лимиту до внесения правок.

## Когда применять сильную модель

Передовую модель имеет смысл оставлять для архитектурных решений, расследований с противоречивыми доказательствами, оценки безопасности, сложных изменений нескольких подсистем и финального ревью. Для механических правок, форматирования, простых тестов и обновления документации подходит более быстрый/доступный режим, если он есть в вашем тарифе. Переход на другую модель не обходит лимиты учётной записи; набор доступных моделей и квот зависит от текущего плана.

Файл Markdown не «сохраняет токены» автоматически: его содержимое всё равно читается моделью. Экономия появляется от коротких стабильных правил, точных ссылок на файлы и отказа от пересылки длинных логов и всей истории в каждом запросе. Для больших логов указывайте файл, временной интервал, объект и конкретную ошибку; пусть Codex сам найдёт нужные строки.

Если лимит уже исчерпан, Codex не сможет продолжить на той же квоте до её восстановления. Реальные варианты — доступный более экономный режим, изменение плана/лимитов или отдельное API-использование с биллингом, если такой способ вам подходит и доступен. Создание нового чата, перенос контекста в `.md` или запуск дополнительных агентов квоту не сбрасывают.

## Шаблон запроса для нового этапа

```text
Работаем только над Pulse в этом репозитории. Прочитай AGENTS.md и
docs/CODEX-STATE-RU.md, затем только файлы, относящиеся к задаче.

Проблема: <конкретный симптом и объект>.
Ожидаемое поведение: <что должно увидеть пользователь>.
Проверка: <команда, API или сценарий>.

Найди подтверждённую причину, исправь её, запусти нужные проверки,
обнови состояние проекта и сообщи, что ещё нельзя подтвердить без
живого кластера/Astra/LLM. Не повторяй общий аудит, если он не нужен.
```

Для выпуска дополните запрос: «проверь сквозные сценарии, полный набор тестов, Docker-сборку и точный build ID; подготовь обновление с сохранением runtime». Для ИИ-расследования задайте критерий: ответ должен ссылаться на выбранный UID и проверенные события/логи, а недоступные источники должны быть указаны отдельно.
