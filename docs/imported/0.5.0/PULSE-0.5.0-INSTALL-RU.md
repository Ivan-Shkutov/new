# Pulse Clusters 0.5.0 — установка и эксплуатация

Полный комплект для одного Linux-сервера. Основной путь: один контейнер Pulse, существующий vLLM на том же сервере, внешние Kubernetes и Astra. Порты/credentials вашей инфраструктуры задаются после установки. Этот документ заменяет последовательность старых инструкций 0.2/0.4 и разрозненных патчей.

## 1. Состав и требования

В архиве: Python backend, веб-интерфейс, Compose, полный wheelhouse CPython 3.12/Linux amd64, тесты, RBAC, шаблоны настроек, каталог официальной документации, скрипты эксплуатации. Не вложены базовый Docker-образ Python, образы Holmes/AURA, GPU-драйверы, веса Qwen/embeddings и полные сторонние руководства.

Хост: Linux amd64, Docker Engine с Compose v2 (`up --wait`), Python 3.10+, доступ root для подготовки числовых UID/GID. Рекомендуемый начальный резерв для Pulse — 4 vCPU/4 GiB RAM и место под документы/историю. Это стартовая конфигурация, не результат нагрузочного теста на вашем числе кластеров. vLLM/GPU и Astra потребляют отдельные ресурсы.

Из Pulse должны быть доступны:

| Назначение | Направление / пример |
|---|---|
| Kubernetes API | Pulse → доступный HTTPS endpoint каждого кластера, обычно 6443 |
| Метрики | Pulse → Prometheus/VictoriaMetrics/vmauth, со scope кластера |
| Astra logs/incidents | Pulse → URL панели/API Astra; логин и права чтения |
| Локальная модель | Pulse → `127.0.0.1:8002/v1` при существующем vLLM |
| Дополнительный Holmes | Pulse → `127.0.0.1:5051`; Holmes → Pulse и vLLM |
| Браузер | HTTPS reverse proxy или SSH-туннель к `127.0.0.1:8090` |

Compose использует `network_mode: host` на Linux: localhost vLLM остаётся localhost. Kubernetes Service DNS/ClusterIP не становятся доступными с этого сервера автоматически. Нужны маршрутизация, VPN или опубликованный аутентифицированный endpoint. Не меняйте адреса по предположению; используйте реально доступные с p0-app5000.

## 2. Установка рядом со старым Pulse

Windows PowerShell, архив в Downloads:

```powershell
scp "$env:USERPROFILE\Downloads\pulse-clusters-0.5.0-complete.tar.gz" dito@10.129.160.10:/home/dito/
```

Это прежний адрес p0-app5000; замените при изменении. На сервере, от root:

```bash
mkdir -p /opt
tar -xzf /home/dito/pulse-clusters-0.5.0-complete.tar.gz -C /opt
cd /opt/pulse-clusters-0.5.0
./pulse verify
./pulse init --port 8090
```

Не распаковывайте поверх собственного изменённого каталога того же выпуска. `verify` проверяет MANIFEST.sha256 каждого файла; внешнюю SHA256 архива можно сверить с присланным рядом файлом. `init` повторяемый: существующие пароль, env и документы сохраняются.

### Перенос из runtime-v3, если нужен

Для существующего 0.4.1 используйте импорт **до первого запуска новой панели**, пока новый `runtime/data` пуст. Сначала сохраните штатную копию старой версии, затем остановите только старую панель для согласованности документов:

```bash
cd /root/pulse-clusters
./pulse3 backup
./pulse3 stop

cd /opt/pulse-clusters-0.5.0
./pulse import-legacy /root/pulse-clusters/runtime-v3
```

Если backup старой версии сообщает ошибку, сначала разберите её и не считайте копию готовой. vLLM и Astra этими командами не останавливаются. Импорт копирует config, kubeconfig, secrets, knowledge, skills, загруженные документы и SQLite через SQLite Backup API. Исходные файлы не меняются. Старые OIDC-сессии удаляются в копии. Незавершённые задания помечаются прерванными переносом, чтобы не повторять модельные вызовы автоматически.

Сохраняются старые настройки авторизации, но новый порт и Compose project остаются отдельными. Внутриконтейнерные пути `/app/kube`, `/app/config`, `/run/pulse-secrets` сохраняются. Если вы использовали нестандартные абсолютные пути, внешний PostgreSQL, внешнее object storage или ссылки на файлы, сначала перенесите/смонтируйте их отдельно: универсальный импорт таких вариантов не реализован. Для 0.2.0 имеется `scripts/export-v2.py` и CLI `import-v2`, но этот путь не равен импорту runtime-v3.

После успешного переноса старые данные остаются на месте. Для отката можно остановить новый Pulse и запустить старый `./pulse3 start-offline`; новые записи обратно автоматически не переносятся.

### Сборка и запуск

```bash
docker version
docker compose version
docker image inspect python:3.12-slim
```

Если базового образа нет, на машине с доступом к реестру:

```bash
docker pull --platform linux/amd64 python:3.12-slim
```

При необходимости зафиксируйте одобренный digest в `runtime/.env`, переменная `PYTHON_BASE_IMAGE`. Не подменяйте базу Alpine или другим Python: вложенные wheels рассчитаны на glibc/CPython 3.12/amd64.

```bash
./pulse start
./pulse status
curl --fail --silent --show-error http://127.0.0.1:8090/healthz
```

Ожидается версия `0.5.0` и статус процесса `ok`. Сборка устанавливает зависимости из wheelhouse с `--no-index --require-hashes`, сетевой доступ на RUN выключен. `tmpfs` задан одним элементом `/tmp:rw,noexec,nosuid,size=256m,mode=1777`; прежняя ошибка «invalid mount path: noexec» устранена в Compose.

## 3. Доступ к интерфейсу

Случайный пароль новой установки:

```bash
cd /opt/pulse-clusters-0.5.0
cat runtime/secrets/portal-password
```

Новый логин — `pulse`. После миграции смотрите `PORTAL_USERNAME`, `PORTAL_USERS_FILE`, `AUTH_MODE` в `runtime/.env`. Credentials не требуется отправлять в чат.

На Windows откройте отдельный PowerShell и оставьте туннель работать:

```powershell
ssh -N -L 8090:127.0.0.1:8090 dito@10.129.160.10
```

Откройте `http://127.0.0.1:8090`. При занятом локальном порту используйте `-L 18090:127.0.0.1:8090` и браузерный порт 18090. Ошибка DNS `p0-app5000` решается использованием IP либо настройкой SSH alias/DNS.

Для общего доступа настройте существующий HTTPS reverse proxy по `deploy/nginx.example.conf`: замените доменное имя и пути сертификата, оставьте backend на localhost:8090. Конфигурация NGINX устанавливается и проверяется на вашем reverse proxy отдельно. Basic передаёт пароль в HTTP-заголовке, поэтому для сетевого доступа используйте TLS или SSH-туннель.

`APP_HOST=0.0.0.0` в `runtime/.env` откроет HTTP на всех интерфейсах; применяйте только в согласованной схеме сети/прокси. Для применения env: `./pulse start-offline`. Для изменения порта редактируйте APP_PORT; у NGINX/SSH должен совпадать backend-порт.

## 4. Подключение Kubernetes

### Подготовить минимальные права

На административный узел/рабочую станцию с kubectl перенесите:

- `deploy/rbac-readonly.yaml`;
- `scripts/export-kubeconfig.py`;
- при выборе долговременного SA-токена — `deploy/serviceaccount-token.yaml`.

Проверьте context, затем примените RBAC в нужном кластере:

```bash
kubectl config current-context
kubectl apply -f rbac-readonly.yaml
kubectl auth can-i list pods --all-namespaces --as=system:serviceaccount:pulse-observer:pulse-reader
kubectl auth can-i get pods/log --all-namespaces --as=system:serviceaccount:pulse-observer:pulse-reader
```

Манифест создаёт namespace `pulse-observer`, SA `pulse-reader`, ClusterRole и binding. Права: get/list/watch определённых типов; pods/log — get. Нет Secret, exec, patch/delete/create workload. `SECRETS: 0` у ServiceAccount само по себе не является ошибкой.

Для начальной проверки экспортируйте краткосрочный токен:

```bash
python3 export-kubeconfig.py \
  --context "$(kubectl config current-context)" \
  --duration 24h \
  --output peoplehub-reader.json
```

Фактический срок определяет Kubernetes API; скрипт выводит expiry, но не токен. Если admin context содержит loopback-адрес, добавьте `--server https://ДОСТУПНЫЙ-API:6443`. Этот адрес должен быть доступен из Pulse и присутствовать в сертификате API. Не отключайте проверку TLS.

Для непрерывного использования без ежедневного ручного экспорта, если политика допускает долговременный ограниченный SA-токен:

```bash
kubectl apply -f serviceaccount-token.yaml
python3 export-kubeconfig.py \
  --context "$(kubectl config current-context)" \
  --token-secret pulse-reader-token \
  --output peoplehub-reader.json
```

Такой токен не имеет автоматически заданного короткого expiry и требует управляемой ротации. Его область ограничивается приложенным RBAC. Если политика требует короткие TokenRequest credentials, обновляйте kubeconfig штатным процессом ротации до expiry; автоматического получения нового Kubernetes токена без исходного доверенного credential в Pulse нет. Срок JWT показывается в настройках как справочная информация.

### Добавить в веб

Pulse → Настройки → Добавить кластер:

| Поле | Пример / смысл |
|---|---|
| ID | `peoplehub`, уникальный и неизменный |
| Название | PeopleHub |
| Окружение / расположение | PROD / ваш ЦОД |
| Kubeconfig | файл `peoplehub-reader.json` либо его текст |
| Context | можно оставить пустым: берётся current-context файла |
| Сбор | включён |

Принимается автономный kubeconfig с встроенными CA/cert/key data и token. `exec`, `auth-provider`, ссылки на локальные credential-файлы и отключённая TLS-проверка отклоняются. Не загружайте admin kubeconfig вместо reader.

Сохраните и нажмите «Проверить источники». Фоновый сбор увидит изменение примерно через 3 секунды; сам сбор занимает время ответа API. До первого снимка показывается «Первичный сбор», без выдуманных количеств. Обычный интервал — 30 секунд.

Новый кластер добавляется тем же способом. Для замены токена/CA откройте «Настроить» и загрузите новый файл; пустое поле сохраняет прежний. «Приостановлен» останавливает будущий polling и скрывает активное подключение, сохраняя настройки и историю. Уже начатый сетевой запрос может закончиться по своему timeout.

## 5. Метрики и Astra Monitoring

### Метрики

В настройках кластера задайте URL Prometheus-совместимого API **до** `/api/v1/query`. Примеры формы адреса:

- `https://prometheus.example.internal`;
- `http://VM-HOST:8428` для соответствующего single-node API;
- адрес vmauth с вашим правильным tenant/path, например `https://metrics.example.internal/select/0/prometheus`.

Это примеры формы, не обнаруженные адреса ваших сервисов. У общего хранилища выберите «Общий» и задайте реальную метку, например `{"cluster":"peoplehub"}`. Название метки нельзя угадывать; проверьте labels серии в вашей системе. Для отдельного Prometheus только одного кластера можно выбрать «Выделенный» и пустые labels.

Доступны Basic username/password, Bearer token и собственный CA PEM. Пустой пароль при редактировании сохраняет старый. Внесённые секреты не возвращаются браузеру. Для смены схемы авторизации прежний credential нужно явно убрать через административный API/конфигурацию, а не оставлять одновременно два типа.

Проверяемые семейства: container CPU/memory, kube-state-metrics requests/limits и capacity, node_exporter CPU/RAM/filesystem/network, kubelet_volume_stats для PVC. Возможности экспортеров и разрешённые метрики определяются вашей установкой Astra.

Для ранее наблюдавшихся нулевых count(kubelet_volume_stats_used_bytes/capacity_bytes) новый Pulse не подставляет нули заполнения. Инвентарь PVC/ёмкость из API будут видны, фактическое использование — «нет данных». Проверяйте kubelet scrape, тип/драйвер тома, поддержку volume stats, labels и фильтры. Наличие kubelet targets или kube_persistentvolumeclaim_info не доказывает наличие usage.

### Astra API: логи и инциденты

Официальная документация: https://am-docs.astra.ru/latest/komponents/api.html и `admin-back.html` рядом. Swagger установленного сервера: `https://ВАША-ASTRA/api/v1/docs/index.html`. Версия платформы и версия Helm-чарта агента — разные параметры.

В форме кластера:

| Поле | Смысл |
|---|---|
| URL Astra | базовый адрес панели, без `/api` |
| Пользователь / пароль | учётная запись с правами чтения нужных логов и инцидентов |
| Bearer token | альтернатива логину; имеет собственный срок, сам не продлевается |
| Поле кластера логов | например `labels.cluster`, строго по фактической записи |
| Значение кластера | например `peoplehub`, одинаковое с маркировкой ваших источников |
| Namespace / Pod | например `labels.k8s.namespace.name`, `labels.k8s.pod.name` |
| Метка кластера инцидентов | имя внутри labels инцидента, например `cluster` |
| CA PEM | доверенный CA вашей Astra, если нужен |

Для логина/пароля адаптер получает токен через POST `/oauth/login`, обновляет доступ повторной аутентификацией до истечения и делает одну повторную авторизацию при 401. Это избавляет от ручного копирования пяти-минутного access_token. SSO с обязательным MFA или отключённым password grant требует одобренного сервисного способа доступа либо ClickHouse-адаптера; Pulse не обходит настройки IdP.

Исторические логи: POST `/api/v1/logs/search/monitorLogs` (это запрос чтения), time/query/paging. Документированный contains-фильтр дополнен **точным** совпадением cluster/namespace/pod на стороне Pulse. Строки другого кластера не попадают в UI/LLM. Ограничения: до 1000 возвращаемых строк, до 4 страниц; неполнота указывается. Нулевая выборка не доказывает отсутствие ошибок; проверяйте labels, время и доставку логов.

Инциденты: GET `/api/v1/is/incidents/`, resolved=false, пагинация до 500 просканированных записей за сбор. Включаются только записи с точной меткой кластера. Если достигнут предел, полнота не утверждается. Поля/уровни берутся из официального контракта, совместимость установленной версии надо подтвердить. Записи без метки кластера не смешиваются с чужими.

Текущие логи Kubernetes и лог предыдущего запуска доступны из карточки Pod отдельно. Можно выбрать обычный или init-контейнер. Для предыдущего запуска агент обращается к Kubernetes даже при настроенной Astra.

### Альтернативный ClickHouse-доступ

В коде сохранён адаптер параметризованных SELECT. Примеры: `config/clickhouse.example.json`, `config/clickhouse-astra-map.example.json`. Сначала проверьте реальную схему `astra.logs` и пользователя только для чтения. Нужен явный cluster column/value, проверенный scope по node/agent либо отдельное представление одного кластера. Названия columns/map keys из примера нельзя считать вашей схемой.

Расширенную секцию `clickhouse` можно передать административному API подключения либо хранить в `runtime/config/clusters.json` для файлового подключения. Если этот ID уже управляется в веб, запись реестра имеет приоритет над файлом. ClickHouse настраивается администратором; в основной веб-форме доступен Astra HTTP API.

## 6. Локальная LLM, Holmes и AURA

### Основной путь — встроенный агент + существующий vLLM

```bash
curl --fail --silent --show-error http://127.0.0.1:8002/v1/models
```

Если vLLM требует ключ, используйте ваш настроенный способ аутентификации; отсутствие ключа не означает неисправность сервера. В Pulse → Настройки → LLM задайте:

- режим «Встроенный агент → vLLM»;
- URL `http://127.0.0.1:8002/v1`;
- точный model ID из ответа, ранее у вас `qwen`;
- API key/CA при наличии;
- максимум 6 шагов, 150 секунд, 1800 output tokens как стартовые значения;
- размер контекста, соответствующий фактическому `--max-model-len` vLLM.

Сохраните → «Проверить ответ и tool calling». Проверка действительно делает два HTTP-вызова: модель вызывает безопасный тестовый инструмент и должна вернуть непредсказуемое заранее значение из его результата. `/v1/models` отдельно недостаточен.

Для automatic tool calling в vLLM нужны поддерживаемая модель, корректный chat template, `--enable-auto-tool-choice` и соответствующий parser. Официальный справочник вашей версии: https://github.com/vllm-project/vllm/blob/v0.30.0/docs/features/tool_calling.md. Не применяйте parser `hermes`/`qwen3_xml` только по сходству имени модели: формат конкретных локальных весов и шаблона должен совпадать. Проверьте доступные параметры `vllm serve --help` внутри используемого образа и текущий конфиг. Pulse не перезаписывает ваш vLLM и шаблон автоматически.

Встроенный агент не требует JSON-schema ответа от модели: получает обычный ответ и реальные tool_calls, ограничивает повторения, время и размер контекста. Разрешены функции чтения объектов, событий, метрик, Pod usage, логов, документации, прошлых проверенных инцидентов и текущих Astra incidents. Произвольного shell, SQL, URL или выбора чужого cluster_id у инструментов нет. Ответ модели остаётся гипотезой до подтверждения оператором.

### Отдельный Holmes для PeopleHub

Сначала настройте и проверьте глобальный vLLM, затем:

```bash
cd /opt/pulse-clusters-0.5.0
docker image inspect us-central1-docker.pkg.dev/genuine-flight-317411/devel/holmes:0.45.0
./pulse holmes peoplehub --port 5051
```

Если образ отсутствует, загрузите его на разрешённой машине/через внутренний реестр. У вас ранее был загружен именно этот тег. Для фиксации содержимого можно передать `--image РЕЕСТР/ОБРАЗ@sha256:...`.

Команда создаёт `runtime/holmes/peoplehub/{compose.yaml,config.yaml,model_list.yaml,.env}`, отдельный зашифрованный токен чтения Pulse и выбирает Holmes для этого кластера. Файлы содержат credentials. Затем выполните напечатанную команду или:

```bash
docker compose \
  --project-name pulse-holmes-peoplehub \
  --project-directory /opt/pulse-clusters-0.5.0/runtime/holmes/peoplehub \
  -f /opt/pulse-clusters-0.5.0/runtime/holmes/peoplehub/compose.yaml \
  up -d --pull never

./pulse check --cluster peoplehub
./pulse accept --cluster peoplehub
```

Порт 5051 выбран, чтобы не занимать прежний 5050. Для второго кластера задайте другой порт и отдельную конфигурацию. Генератор не перезаписывает существующий каталог/экспорт, чтобы случайно не ротировать токен работающего экземпляра.

В `config.yaml` установлен `max_steps: 6`. Отключены Kubernetes, bash, internet и другие перечисленные встроенные tools; настроен ограниченный GET HTTP toolset Pulse для одного `/api/tools/ID/*`. kubeconfig и Docker socket в Holmes не монтируются. MODEL alias — `qwen-local`, фактическая модель берётся из глобальных настроек vLLM. Проверьте список активных tools в конкретном образе Holmes. Генератор конфигурации проверен локально; сам образ здесь не запускался.

Внешний Holmes должен поддерживать `/healthz`, `/api/model`, `/api/chat` и используемый контракт structured response. При ошибке схемы/лимита Pulse сохранит ошибку задания. Не считайте healthy успешным расследованием. Веб → настройка кластера → секция Holmes → «Глобальные настройки LLM» возвращает встроенный движок, если глобально выбран vLLM.

Генератор переносит context/output limits из глобальных настроек LLM и ограничивает отдельный запрос модели 60 секундами. Проверьте соответствие фактическому vLLM. Отмена ожидания в Pulse не гарантирует остановку уже выполняющегося запроса во внешнем Holmes; его собственный цикл ограничен max_steps. Для HTTPS vLLM с частным CA добавьте доверенный CA в контейнер Holmes по правилам этого сервиса; CA только в Pulse не меняет доверенные сертификаты Holmes.

### AURA

Для отдельно установленной AURA с OpenAI-compatible webserver можно выбрать режим AURA, базовый URL `http://HOST:PORT/v1` и model ID/agent alias из `/v1/models`. Справочник: https://docs.mezmo.com/aura/web-server-reference. Выполните ту же реальную пробу tool calling. Адаптер не разворачивает AURA и не подтверждает поддержку любых её выпусков. Внешние tools AURA должны иметь согласованную область доступа; ограничения Pulse действуют на инструменты, которые исполняет сам Pulse.

## 7. Документы и подтверждённые инциденты

Веб → База знаний: один или несколько MD/TXT/RST/HTML/PDF/DOCX, до 30 MiB каждый. Укажите источник и точную метку версии, например `kubernetes:1.30`. Оператор загружает документ в разрешённый кластер; глобальный администратор может выбрать общий корпус. Файл принимается быстро, парсинг/индексация выполняются в фоне. Следите за статусом «Готов к поиску»/ошибкой и проверьте реальный поисковый запрос.

В настройках кластера задаётся список допустимых версий. Сравнение точное, по всей строке. Пустой список разрешает все версии; документ без версии доступен всегда в пределах своего scope. Это фильтр совместимости, а не автоматическое определение версии продукта. Используйте одинаковые обозначения при загрузке и настройке кластера.

PDF-скан без текста не индексируется; нужен OCR вне Pulse. Ограничения встроенного индекса: 8 млн символов документа, 3000 страниц PDF, 50 000 фрагментов корпуса. При превышении есть ошибка/skipped, а не незаметная успешная индексация. Для большого официального корпуса импортируйте нужные разделы и версии и проверяйте итог `./pulse index`.

Удаление загрузки через «В архив» исключает её из retrieval и перемещает исходник в `runtime/data/document-archive`; на диске остаётся возможность восстановления. Файлы из readonly `runtime/knowledge` администратор изменяет на хосте.

Каталог официальных источников: `docs/official-catalog/index.html`, команды в `DOWNLOAD-RU.md`. Например, на машине с интернетом:

```bash
python3 docs/official-catalog/download_docs.py --list
python3 docs/official-catalog/download_docs.py \
  --ids kubernetes,vllm,holmes,prometheus,kube-state-metrics,node-exporter \
  --download --out /data/Pulse-Official-Docs
```

Скачиваются ZIP исходников по зафиксированным commit SHA. Это не готовые автономные сайты, модели или Docker-образы. После распаковки выберите каталог текстовых документов нужного языка/версии. Для массового импорта:

```bash
python3 scripts/import-docs.py \
  --runtime /opt/pulse-clusters-0.5.0/runtime \
  --source /ПУТЬ/К/РАСПАКОВАННЫМ/content/en/docs \
  --name kubernetes-130-en \
  --version kubernetes:1.30 \
  --cluster peoplehub
./pulse permissions
./pulse index
```

Замените путь источника на реальный. Для общей документации `--cluster '*'`. Нельзя выдавать Markdown с шаблонами генератора сайта за полностью отрендеренную книгу: при необходимости заранее экспортируйте HTML/PDF официального сайта.

Начните с Kubernetes вашей версии, Astra вашей версии, vLLM/модели, Holmes если используется, Prometheus/VictoriaMetrics/ClickHouse и документации ваших приложений. Deckhouse/Ceph/Velero/CNPG/ingress/CNI добавляйте по фактической установке. Версии latest и основной ветки не подменяют документацию установленного продукта.

Для вопроса «Для чего этот Pod?» заполните `docs/templates/SERVICE-RU.md`: приложение, namespace, label/owner, назначение, владелец, зависимости, конфигурация и способы проверки. Официальная документация Kubernetes не знает назначения вашего PeopleHub-компонента.

После расследования: «Сохранить инцидент» → открыть журнал → заполнить фактическое решение и результат проверки → статус resolved → публикация в БЗ. Изменение проверенной записи снимает публикацию. Шаблон человеческого описания — `docs/templates/INCIDENT-RU.md`.

Семантический поиск подключается отдельно: `docs/SEMANTIC-SEARCH.md`. Без него работает локальный FTS5; для русских вопросов к английскому корпусу полезны точные имена сервисов/ошибок и двуязычные внутренние инструкции.

## 8. Приёмка

```bash
./pulse status
./pulse check --cluster peoplehub
./pulse accept --cluster peoplehub
```

Проверьте в UI:

1. Количество узлов/namespaces/Pod соответствует `kubectl get`, включая пустые namespaces. Пройдите страницы списка, проверьте coverage.
2. Время снимка обновляется; отсутствие доступа и устаревание показаны явно. Снимок старше `max(120 секунд, 3×POLL_SECONDS)` не считается зелёным подтверждением состояния.
3. CPU/RAM актуальны, requests/limits имеют единицы. Отсутствующая серия — «нет данных», не 0.
4. Для одного Pod выберите Astra logs и сравните несколько строк/время с оригиналом. Проверьте отсутствие записей другого кластера с таким же именем Pod.
5. Инцидент Astra с меткой выбранного кластера попадает в сигналы. При ошибке источника ранее наблюдавшийся инцидент не считается решённым.
6. В базе знаний находится загруженный документ нужной версии. Вопрос о назначении сервиса опирается на ваше описание, а не на предположение.
7. «! Почему?» завершает анализ в заданных пределах, показывает факты и пробелы. Обновление страницы сохраняет задание/историю без повторной постановки.
8. На известном сбое сравните объяснение с фактической причиной. Исправление оператор выполняет отдельно. После восстановления публикуется проверенное решение.

Зелёный health не заменяет эти проверки. `check` может быть not ready при отсутствии PVC usage даже с доступным Kubernetes — это обозначение неполной информации, а не причина скрывать весь инвентарь.

## 9. Резервное копирование, восстановление, офлайн

### Backup по умолчанию SQLite

```bash
./pulse backup
```

Команда кратко останавливает **только Pulse**, создаёт согласованный архив всего runtime и SHA256, затем запускает Pulse обратно, если он работал. В архиве история, документы, конфигурация и `registry.key`. Без ключа нельзя расшифровать сохранённые подключения. Backup содержит секреты; сохраняйте его в защищённое резервное хранилище, отдельно от сервера. На внешнем PostgreSQL команда откажет: нужны pg_dump и согласованная копия runtime.

Восстановление в установленный runtime:

```bash
./pulse restore /ПУТЬ/pulse-ДАТА.tar.gz --confirm-restore
./pulse start-offline
./pulse check --cluster peoplehub
```

Нужен соседний `.sha256`. До замены проверяются хеш, пути/типы файлов и SQLite integrity. Текущий runtime сохраняется в `runtime.before-ДАТА`, OIDC-сессии из копии отзываются. Если приложение после восстановления не готово, сохранён предыдущий каталог; ничего автоматически не удаляется.

### Полностью закрытый контур

На Linux amd64 машине с Docker и доступом к базовому образу:

```bash
./pulse init
docker pull --platform linux/amd64 python:3.12-slim
./pulse build
./pulse export-image /data/pulse-clusters-0.5.0-amd64.tar
```

Передайте в закрытый контур **исходный complete.tar.gz, образ .tar и его .sha256**. На целевом сервере:

```bash
cd /КАТАЛОГ/С/ОБРАЗОМ
sha256sum -c pulse-clusters-0.5.0-amd64.tar.sha256
docker load --input pulse-clusters-0.5.0-amd64.tar
cd /opt/pulse-clusters-0.5.0
./pulse init --port 8090
./pulse start-offline
```

Для этого пути базовый Python-образ на целевом сервере не нужен: приложение уже собрано в перенесённом образе. Holmes/AURA/vLLM переносятся отдельно, если их ещё нет. На данном стенде нет Docker daemon, поэтому готовый Docker-image tar в присланный комплект не вложен и его сборка здесь не заявляется выполненной.

## 10. Управление и расширение

| Команда | Действие |
|---|---|
| `./pulse verify` | Проверить файлы поставки |
| `./pulse init` | Создать runtime без перезаписи существующих настроек |
| `./pulse start` | Собрать и запустить Pulse |
| `./pulse start-offline` | Запустить имеющийся образ без build/pull |
| `./pulse stop` / `status` / `logs` | Остановить, состояние, журнал |
| `./pulse permissions` | Числовые UID/GID 65532; аккаунт на хосте не требуется |
| `./pulse check` / `accept` | Проверки источников и model/tool chain |
| `./pulse index` | Переиндексировать документы и вывести skipped |
| `./pulse backup` / `restore` | Согласованная копия/восстановление SQLite runtime |
| `./pulse compose ...` | Доступ к Compose только проекта Pulse |

Для нескольких пользователей есть `scripts/add-user.py`, `scripts/add-api-user.py`, примеры OIDC и API-клиент `clients/pulse_client.py`. Управляющие маршруты требуют глобального admin. Изменяющие browser/API-запросы требуют `X-Pulse-Request: 1`; viewer не запускает анализ и не изменяет документы. См. `docs/API-RU.md`.

Встроенный polling/очередь рассчитан на один API-процесс. Не задавайте несколько Uvicorn workers и не запускайте несколько контейнеров на одну SQLite/data: файловый controller lock это запрещает. PostgreSQL не превращает этот выпуск автоматически в HA-систему. Перенос workers, LIST/WATCH и распределённая очередь — отдельное развитие после измерения нагрузки.

Если статическая страница открывается, но конкретный источник не работает, проверяйте его отдельно через «Проверить источники». При сбое LLM инвентарь остаётся доступным. Ошибка AuthlibDeprecationWarning из текущего wheelhouse — предупреждение зависимости, не доказательство отказа источника; результат проверки смотрите в JSON/статусе задания.

Если токен истёк — замените kubeconfig. Если API недоступен — проверьте маршрут/endpoint/CA. Если Prometheus вернул пусто — метки и наличие серии. Если Astra вернула 404/не тот JSON — контракт Swagger установленной версии. Если модель не вызывает tools — её parser/template и параметры vLLM. Если текст скана не найден — OCR. Эти причины не устраняются установкой ещё одного агента.
