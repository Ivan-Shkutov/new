# Pulse 0.9.0 — компактный Обзор, dashboard по нажатию и диалог по проблеме

## Изменения интерфейса

- Верхний ряд: **Узлы Ready / Pods Ready / Критические сигналы**. Карта кластеров и длинные пояснения перенесены в раскрываемую панель.
- Второй ряд: **CPU / RAM / диски**. Круг или карточка открывает большой dashboard с историей, диапазоном 1/6/24 часа, единицами и таблицами исходных серий по узлам, Pod и файловым системам. Есть поиск по instance/pod/mountpoint.
- Третий ряд: **DaemonSets / Deployments / Jobs / CronJobs / ReplicaSets / StatefulSets / Pods** в одну строку на desktop. Клик открывает фактические объекты, состояния и JSON.
- Ниже: таблица проблем с поиском по объекту/namespace/причине, критичностью, временем наблюдения и страницами по 25 строк. Список строится по всей доступной выборке, прежнее ограничение первыми 40 проблемами снято. Полнота по-прежнему зависит от API/RBAC и лимита LIST коллектора.
- **✧ — Разобрать с ИИ.** У каждого сигнала открывается окно с контекстом, вопросом, ответом, продолжением разговора и списком использованных сценариев/источников/tools. Диалог сохраняется в SQLite как задания расследования.

Изображения — браузерные тесты с подписанными тестовыми данными, не метрики серверов пользователя. В приложение тестовые данные не встроены.

Обзор проверен при 100% масштабе браузера на viewport 1920×1080 и 1366×768: без прокрутки внешней страницы, три верхние карточки, три утилизации, семь workloads в ряд. Проблемы прокручиваются внутри своей таблицы и имеют страницы; неограниченное число проблем физически нельзя одновременно показать в одном экране. На узком/низком экране применяется перенос для читаемости. Масштаб браузера менять не требуется; после обновления можно нажать Ctrl+0 и Ctrl+F5.

## Реальные источники

Для утилизации и истории по-прежнему нужен доступный Prometheus/VictoriaMetrics с node_exporter и правильными cluster labels. Без него круги показывают отсутствие данных, большой dashboard — причину и недоступные серии. Дисковый круг означает корневые ФС `/` узлов; в подробностях видны filesystem серии и PVC, если их отдаёт источник. Число CPU cores, bytes available и working set не подменяются процентами.

Список проблем — текущие Kubernetes-сигналы из имеющегося коллектора. Он не является импортом всех логов/инцидентов Astra. Astra incidents API в этот выпуск не добавлен; логи Astra доступны через ранее существующий адаптер после настройки URL/token/mapping.

## Локальная LLM и сценарии проверки

Действующие настройки qwen сохраняются. Базовый режим собирает снимок, выбранный Pod/UID, доступные логи, документы и проверенные решения; это детерминированный сбор контекста, без автономного выполнения команд. В ответе запрошены короткий вывод, подтверждённые факты, гипотеза/альтернативы, безопасные проверки и пробелы. Нельзя гарантировать правильный диагноз одним промптом: проверяйте известные случаи на реальных источниках.

Встроены 9 версионированных сценариев: проверка доказательств, CrashLoop, образы, scheduling, readiness, узлы, rollout, storage, Evicted. Выбираются подходящие сценарию, а не весь корпус сразу. UI показывает фактически выбранные skills и доступность источников. Это сценарии расследования Pulse, не инструкции для изменения инфраструктуры.

Продолжение разговора использует сохранённый контекст проблемы и ограниченную цепочку предыдущих реплик. Для Pod проверяется UID перед чтением логов; новый объект с прежним именем не должен приниматься за старый. Ошибки анализа не подменяются успешным ответом другого движка.

## HolmesGPT — отдельное подключение

[Полная подготовка и приёмка Holmes](HOLMES-RU.md). Добавлен адаптер `/api/chat`, генератор per-cluster Compose/config/model list/skills и ограниченный API чтения Pulse. Режим включается отдельно для выбранного кластера после проверки.

Протокол сопоставлен с официальным HolmesGPT tag 0.45.0, commit `21ca948b8b4935a2ed0aa98dae05449d10953005`. Unit tests проверяют контракт и границы токенов. **Реальный контейнер Holmes в этой облачной среде не запускался:** запрос pull к `us-central1-docker.pkg.dev` получил Forbidden. Ваш прежний образ может быть уже сохранён на сервере; реальную совместимость образа, его tools и tool calling Qwen требуется подтвердить на сервере кнопкой проверки инструментов. Это остающаяся внешняя проверка, не завершённая проверка production-связки.

## Скачать и перенести обновление

Скачайте через Download raw file в авторизованном GitHub:

- `releases/pulse-clusters-0.9.0-complete.tar.gz`;
- `releases/pulse-clusters-0.9.0-complete.tar.gz.sha256`.

На компьютере Windows:

```powershell
scp "$env:USERPROFILE\Downloads\pulse-clusters-0.9.0-complete.tar.gz" dito@10.129.160.10:/home/dito/
scp "$env:USERPROFILE\Downloads\pulse-clusters-0.9.0-complete.tar.gz.sha256" dito@10.129.160.10:/home/dito/
```

На сервере 10.129.160.10 от root, только после успешной передачи файлов:

```bash
(
set -eu
umask 077
cd /home/dito
sha256sum -c pulse-clusters-0.9.0-complete.tar.gz.sha256
tar --keep-old-files -xzf pulse-clusters-0.9.0-complete.tar.gz -C /opt
cd /opt/pulse-clusters-0.9.0
sha256sum -c MANIFEST.sha256
./pulse init --port 8090
./pulse build

pulse_backup_dir="/root/pulse-backup-090-$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 "$pulse_backup_dir"
cd /opt/pulse-clusters-0.8.0
./pulse backup --output-dir "$pulse_backup_dir"
pulse_backup_files=("$pulse_backup_dir"/pulse-*.tar.gz)
test "${#pulse_backup_files[@]}" -eq 1
test -f "${pulse_backup_files[0]}"
./pulse stop

cd /opt/pulse-clusters-0.9.0
./pulse restore "${pulse_backup_files[0]}" --confirm-restore
./pulse start-offline
./pulse check
)
```

Блок предназначен для подтверждённой установки 0.8.0 в `/opt/pulse-clusters-0.8.0`. При ошибке остановитесь, не удаляйте каталоги. Runtime восстанавливается штатным restore: сохраняются PeopleHub, qwen, ключ шифрования, пароль, документы и история. Новые поля контекста/trace добавляются при старте. vLLM не перезапускается.

Откройте прежний туннель, обновите браузер. Проверьте версию 0.9.0, готовность узлов, 7 workloads в один ряд, список проблем, окно ✧ и продолжение диалога. Для настоящих графиков подключите реальный источник метрик. При истечении Kubernetes reader-token обновите его отдельно.

## Откат

В новом каталоге `./pulse stop`, затем в `/opt/pulse-clusters-0.8.0` выполните `./pulse start-offline`. Старый runtime сохранён; новые записи 0.9.0 автоматически обратно не переносятся. Перед откатом сохраните отдельный backup новой установки. Не запускайте два API-процесса на одном runtime.

## Проверки и границы

**136 тестов прошли, пропусков нет.** Pytest проверяет проблемы за пределами первых 40, scope/пагинацию, issue context и follow-up, UID, trace и миграцию, allowlist метрик, контракт Holmes, отказ лишних tools, per-cluster bearer и непредсказуемый challenge. Три Chromium-сценария прошли: экран без внешней прокрутки, полный ряд workloads, dashboard по нажатию, страницы списка, две реплики чата, безопасный вывод HTML и mobile. Docker Pulse собран и запущен; на отдельном стенде проверен переход с 0.8.0 через CLI backup/restore с сохранением пароля, ключа, подключения, qwen, документа и истории.

Приложение остаётся single-process / SQLite / один администратор. Для промышленного внедрения нужны согласованные доступы, HTTPS или SSH-туннель, backup/restore-процедура, retention и проверка нагрузки/диагнозов в вашем контуре. Этот выпуск не делает систему HA и не подтверждает любые внешние интеграции без их живой приёмки.
