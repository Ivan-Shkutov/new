# HolmesGPT для Pulse 0.9.0

Holmes — опциональный отдельный движок расследований. Работающий локальный qwen через vLLM сохраняется как основной режим до явного включения Holmes для конкретного кластера. Сам сервер Holmes, его образ и веса моделей не входят в архив Pulse.

## Подготовка

Сначала обновите Pulse до 0.9.0 и проверьте обычный ответ qwen. В Настройки → PeopleHub → Настроить → HolmesGPT:

1. Выберите свободный порт, по умолчанию 5051. Для второго/третьего кластера — другой порт (например 5052/5053).
2. Нажмите **«Подготовить конфигурацию»**. Генератор использует сохранённый vLLM URL/model и создаёт `runtime/holmes/peoplehub`. Режим Holmes остаётся выключенным.
3. Закройте и заново откройте настройки кластера: URL, alias и наличие защищённого API key сохранены; значения ключей не возвращаются браузеру.

Файлы содержат credentials, права ограничены. Повторная генерация существующего каталога запрещена, чтобы не ротировать работающие токены. Не удаляйте его ради повторного нажатия кнопки. Для vLLM со своим CA генератор откажет: сперва настройте trust в Holmes согласно его документации, не отключая TLS.

## Запуск на вашем сервере

Проверьте наличие ранее использованного образа (это безопасная проверка, ключи не выводятся):

```bash
docker image inspect us-central1-docker.pkg.dev/genuine-flight-317411/devel/holmes:0.45.0 --format '{{.Id}}'
```

Если образ отсутствует, его нужно получить из одобренного реестра с проверкой происхождения/доступа. В нашей среде этот registry ответил Forbidden; готового образа в архиве нет. При необходимости выберите одобренный digest образа в сгенерированном compose перед запуском. Совпадение тега само по себе не подтверждает точную сборку.

После генерации конфигурации для peoplehub:

```bash
docker compose \
  --project-name pulse-holmes-peoplehub \
  --project-directory /opt/pulse-clusters-0.9.0/runtime/holmes/peoplehub \
  -f /opt/pulse-clusters-0.9.0/runtime/holmes/peoplehub/compose.yaml \
  up -d --pull never --wait
```

Сервис привязан к localhost выбранного порта, использует host networking Linux. Работает отдельным UID, без kubeconfig и Docker socket, с read-only root и tmpfs. Wrapper отключает все builtin toolsets из установленного образа, затем включает только `skills` и `pulse-readonly`. Допускаются только GET определённых `/agent/peoplehub/*`, без произвольных URL/SQL/shell/изменений кластера. Токен чтения Pulse не подходит к другому cluster_id и не даёт доступа к обычным административным API.

В конфигурации max_steps=6, запрос модели ограничен timeout 60 секунд. Вызов из Pulse имеет timeout 180 секунд; прекращение ожидания клиентом не гарантирует немедленную остановку уже начатого внешнего вызова. Окончательный бюджет зависит и от сервера Holmes. Проверяйте его при нагрузке.

## Приёмка

В настройках кластера:

1. Нажмите **«Проверить ответ Holmes»**. Pulse сначала читает `/api/info?detail=full`, требует auth_enabled и допускает активные только `pulse-readonly`/`skills`. Затем делает `/api/chat`. Неподдерживаемый контракт или лишние tools блокируют запрос.
2. Нажмите **«Проверить инструменты»**. Pulse создаёт временный непредсказуемый nonce, не передаёт его модели, и просит Holmes прочитать через разрешённый HTTP tool `/agent/peoplehub/challenge`. Только получение правильного результата подтверждает фактический tool call. Обычный текстовый ответ не проходит эту проверку.
3. Только после успешных проверок включите **«Использовать Holmes для этого кластера»** и сохраните.
4. Откройте существующую проблему → ✧ → вопрос. В раскрываемых источниках проверьте сценарии, engine HolmesGPT и вызванные tools. Сопоставьте результат с известным фактом/инцидентом. Не создавайте аварии в production ради проверки.

Если tool calling не работает, проверьте реальные возможности модели, chat template, parser и параметры именно вашей версии vLLM. `/v1/models` и обычный текстовый ответ не подтверждают работу инструментов. Не выбирайте `hermes` или другой parser только по имени qwen и не перезапускайте vLLM с непроверенными параметрами. Справочник: https://docs.vllm.ai/en/latest/features/tool_calling/.

Если `/api/info` отсутствует, неподдерживаемый/старый образ нужно заменить на сборку с проверенным контрактом; обход проверки отключением auth/tools не предусмотрен.

## Сценарии и качество

В bundle экспортируются 9 `SKILL.md`: общая проверка доказательств, CrashLoop, образы, scheduling, readiness, узлы, rollout, storage, Evicted. Pulse также выбирает относящиеся к вопросу сценарии и добавляет их к системному контексту. Данные инструментов, логов и документов считаются недоверенным контентом. Ответ должен разделять наблюдения, гипотезы, безопасные проверки и пробелы.

Эти ограничения не являются доказательством правильного диагноза. Промышленная приёмка требует известных случаев, проверки источников, утечек/изоляции и нагрузки. Администратор внешнего Holmes контролирует его конфигурацию; проверка имён tools в Pulse не заменяет проверку их whitelist-конфигурации.

## Проверенный исходный контракт

Официальный репозиторий: https://github.com/robusta-dev/holmesgpt/tree/21ca948b8b4935a2ed0aa98dae05449d10953005 (tag 0.45.0).

Сопоставлены `server.py`, `holmes/core/models.py`, `holmes/config.py`, HTTP toolset и skill loader. `/api/chat` получает ask/model/conversation_history/additional_system_prompt/stream=false, возвращает analysis/tool_calls. Реальный контейнер в нашей среде не запускался из-за запрета registry; это явно непроверенная часть, которую завершают шаги приёмки на вашем сервере.
