# Повторный аудит 0.16.1

База повторной проверки — опубликованный 0.16.0. Основная архитектура, шесть разделов ответа, 16 инструкций Holmes, импорт библиотеки и read-only доступ сохранены. [Приняты решения по всем десяти вопросам](PROJECT-DECISIONS-RU.md).

## Подтверждённые исправления

- **Неравные лимиты контекста.** Native и Astra допускали 240 000 символов суммарно, но отвергали отдельное сообщение свыше 100 000. Крупный запрос с доказательствами мог не попасть в модель. Проверка теперь общая для всех трёх адаптеров и считает все сообщения; новый тест отправляет 110 000 символов в одном сообщении. Незаметного обрезания нет.
- **Проверка входа Holmes.** Ранее список/роли/общий размер сообщений не проверялись адаптером до HTTP. Некорректные/слишком большие запросы теперь отвергаются до сетевого обращения. Это локальная валидация, не гарантия вместимости tokenizer модели.
- **Совместная нагрузка.** Заданы один активный разбор, один ожидающий и 60 секунд ожидания. Эти настройки доступны в Compose и возвращаются в API settings. Время очереди видно в trace; перегрузка/истечение ожидания не выглядят ошибкой генерации или исправным инцидентом.
- **Закрытые и просроченные запросы.** Ожидающие задачи удаляются без обращения к модели и возвращают ёмкость очереди ровно один раз. Данные отменённых запросов не накапливаются за медленным активным вызовом; проверено освобождение объектов при повторных закрытиях. Активная удалённая генерация при закрытии не отменяется этим механизмом.

Дополнительно запрещены HTTP redirects в `pulse-doctor.py` и `live-acceptance.py`, чтобы Basic credentials не отправлялись другому origin. Operator HTTP не использует случайный ambient proxy; HTTPS продолжает проверять сертификат. Ожидание live-acceptance включает бюджет очереди, сбор/поиск и выбранного провайдера, вместо прежних фиксированных 420 секунд.

Полные правила расследования повторно проверены: факт не равен гипотезе; `SendText` не означает подтверждённую доставку; stderr не равен error; расшифровки внутренних полей VK не придумываются; документация не доказывает текущее состояние кластера. Для живой модели сформулированы [случаи приёмки](ACCEPTANCE-CASES-RU.md).

## Границы проверки

Локальные тесты и HTTP fixtures проверяют контракт, управление задачами и передачу данных. Веса Qwen, фактический Holmes, BGE-M3 и production-доступ пользователя требуют приёмки на сервере. Не утверждается, что увеличение токенов обучает модель или делает её эквивалентом инженера с определённым стажем. Действующие бюджеты 8192/300 и 8×4096/180 с ожиданием 600 остаются настраиваемыми.

Увеличение параллельности всех клиентов vLLM, автоматические исправления, новые полномочия Kubernetes, SSO, n8n и произвольный shell не добавлялись. Непроверенные версии приложений и права API не выбирались как вымышленные факты. Известные ограничения 0.16.0 остаются в [первом аудите](AUDIT-0.16.0-RU.md).
